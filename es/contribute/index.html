Ayuda a mejorar este libro

Esta obra libre está abierta a contribuciones para mejorar las explicaciones, el código y los laboratorios.

Formas de ayudar

  • Informar de una errataUna falta de ortografía, una palabra que falta, una frase poco clara.
  • Corregir una traducciónUn pasaje erróneo o poco natural en una traducción.
  • Corrección técnicaUna afirmación sobre Tor que es errónea o está desactualizada.
  • Problema en un laboratorioUn laboratorio que no se comporta como se describe.
  • Proponer una mejoraContenido nuevo, una explicación mejor, una figura.
  • Revisión de las traduccionesRevisa un capítulo en tu idioma.
  • Aportar texto o códigoAbre una pull request.
  • Mejorar la documentaciónREADME, guías, instrucciones.

Sin Git ni LaTeX

Solo necesitas una cuenta de GitHub. Elige el tipo de aviso, rellena el formulario — el idioma, el capítulo o la página, el texto actual y lo que escribirías en su lugar — y envíalo. Con eso basta: otra persona hará el cambio en las fuentes.

Para una errata pequeña también puedes proponer tú la corrección: abre el archivo en GitHub, pulsa el icono del lápiz, cambia el texto y elige «Propose changes». GitHub crea por ti una copia del repositorio y una pull request; no hace falta compilar el libro.

Con Git

  1. Abre primero una issue, salvo que el cambio sea una corrección pequeña.
  2. Localiza el archivo: el texto italiano está en source/it/, las traducciones en source/<idioma>/, el código de los laboratorios en labs/.
  3. Haz un fork del repositorio, crea una rama y aplica el cambio.
  4. Ejecuta las comprobaciones adecuadas: make check y make test solo necesitan Python; para compilar el libro hace falta Docker.
  5. Abre una pull request y responde a la revisión.

Los detalles están en CONTRIBUTING.md (en inglés y en italiano).

Qué pasa después

Cada aviso se lee y recibe un estado: por verificar, confirmado, en curso, corrección propuesta, resuelto, no reproducible o duplicado. Los cambios en la descripción del protocolo, en la criptografía o en los laboratorios requieren una fuente primaria o una prueba reproducible; para una errata basta una comprobación rápida. Las correcciones aceptadas entran en la siguiente versión del libro y se recogen en el registro de cambios. El proceso se describe en docs/editorial-process.md.

Reconocimiento

Quienes aportan cambios aceptados aparecen en CONTRIBUTORS.md, con su nombre de GitHub o el nombre que prefieran. Cualquiera puede pedir no aparecer. No hay clasificaciones.

Conviene saber

  • Las contribuciones se aceptan bajo la licencia del proyecto, GPL-3.0-or-later.
  • No pongas en las issues públicas datos personales, claves privadas, capturas de tráfico ni otro material sensible.
  • Los problemas de seguridad en el código o en los laboratorios se comunican en privado: véase SECURITY.md.
  • Se espera que todas las personas respeten el breve código de conducta.
