# Автоматическая проверка

Русское издание располагает самостоятельным деревом `labs/ru/`. Наличие тестов и сценариев **не доказывает, что они были исполнены и охватывают все эксперименты**. Автономные Python-тесты, проверка сети Chutney и специальные опыты выполняются отдельно. Docker использует `--network host`, поэтому разные издания разделяют порты хоста.

## Основные команды

Из корня репозитория (при первом использовании сначала соберите образ с доступом к Интернету):

```bash
PYTHONPATH=labs/ru/код python3 -m pytest -q labs/ru/код/torlab/test
make -C labs/ru/лаборатория image       # впервые: скачать Tor, Chutney и зависимости
make -C labs/ru/лаборатория start
make -C labs/ru/лаборатория verify
make -C labs/ru/лаборатория status
```

Первая команда запускает автономные модульные и регрессионные тесты `torlab` с сохранёнными данными; **она не запускает Tor или HTTP-сервер на порту 8080**. Проверяются форматы, эталонные векторы, обработка ошибок, разбор данных, криптографические операции и вычисления. Число и результаты тестов следует определять при их реальном запуске.

Вторая команда запускает приватную топологию `book`. Третья выполняет сквозную проверку Chutney для активной топологии. Четвёртая показывает состояние узлов.

## Тесты кода

Русский набор тестов расположен в `labs/ru/код/torlab/test/`. Для него не требуется публичная сеть Tor.

Основные категории:

- **Тесты форматов протокола** для ячеек, каналов, документов каталога и сообщений ретрансляции.
- **Криптографические тестовые векторы**, включая предложение 332 для ntor-v3 и предложение 216 для HKDF ntor.
- **Отрицательные тесты** для изменённых подписей, ошибочных значений аутентификации, просроченных сертификатов, некорректных длин и несовпадающих идентификаторов.
- **Тесты воспроизводимости** вычислений, используемых в книге.

Одного успешного теста корректного ввода недостаточно. Проверяющая функция, принимающая любой ввод, тоже прошла бы такой тест, поэтому в набор намеренно входят случаи, которые должны завершаться ошибкой.

## Проверка приватной сети

Запустите стандартную русскую топологию:

```bash
make -C labs/ru/лаборатория start
make -C labs/ru/лаборатория verify
```

Цель `verify` вызывает Chutney для активной топологии и проверяет сквозную доставку. После этого по отдельности запускают сценарии в `labs/ru/лаборатория/`: ограниченное обнаружение onion-сервиса, политику выхода, корреляцию собственного трафика, признаки утечки DNS и лимит `RELAY_EARLY`. **Эти программы могут временно изменять конфигурацию узлов и открывать локальные серверы; Chutney `verify` не запускает их автоматически.** Используйте только частную сеть и следуйте инструкциям лабораторий.

Примеры:

```bash
PYTHONPATH=labs/ru/код python3 labs/ru/лаборатория/exit_policy.py
PYTHONPATH=labs/ru/код python3 labs/ru/лаборатория/restricted_discovery.py
PYTHONPATH=labs/ru/код python3 labs/ru/лаборатория/relay_early.py 8 9
```

## Bridge-топология

Лабораторная работа 10 использует `book-bridge`, отдельную от обычной топологии `book`:

```bash
make -C labs/ru/лаборатория clean
make -C labs/ru/лаборатория start NETWORK=book-bridge
make -C labs/ru/лаборатория verify
```

**Внимание:** команда `clean` уничтожает всё содержимое `labs/ru/лаборатория/net/`, включая закрытые ключи и идентификаторы onion-сервисов. Сохраните необходимое перед сменой топологии. В `book-bridge` 12 узлов, обычного onion-сервиса `009h` там нет.

После завершения:

```bash
make -C labs/ru/лаборатория clean
make -C labs/ru/лаборатория start
```

Цель `verify` сама топологию не переключает: она проверяет ту, которая запущена сейчас.

## Как интерпретировать ошибки

| Симптом | Вероятное объяснение |
|---|---|
| Сетевой эксперимент один раз завершается ошибкой, а при повторе проходит | Сохраните журналы и выясните причину: успешный повтор не доказывает корректности. |
| Один и тот же шаг стабильно завершается ошибкой | Исследуйте возможную регрессию кода, конфигурации или окружения. |
| Не проходят все сетевые эксперименты | Проверьте `make -C labs/ru/лаборатория status` и журналы authorities в `labs/ru/лаборатория/net/nodes/`. |
| Криптографический отрицательный тест неожиданно проходит | Проверьте логику: программа может принимать недопустимый ввод. |
| Вычисления по опубликованному снимку отличаются | Проверьте совпадение архивного консенсуса, контрольных сумм и даты. |

## Перед публикацией выпуска

Как минимум выполните:

```bash
PYTHONPATH=labs/ru/код python3 -m pytest -q labs/ru/код/torlab/test
make -C labs/ru/лаборатория start
make -C labs/ru/лаборатория verify
```

Затем запустите каждый сценарий, результаты которого цитируются в книге, и проверьте **код завершения, журналы и наблюдения**, а не только строки вывода. Значения, зависящие от времени, новых ключей onion-сервиса, консенсуса или захвата пакетов, могут меняться; структура протокола должна сохраняться. Ни pytest, ни Chutney `verify` отдельно не проверяют все двадцать работ.

Русские команды должны ссылаться на `labs/ru/`. Итальянские `make verifica-lab` и `make verifica-lab-bridge` **не сертифицируют русскую среду**. EN/RU/ZH-CN разделяют имя контейнера `torbook-network` и порты, поэтому их нельзя запускать одновременно.
