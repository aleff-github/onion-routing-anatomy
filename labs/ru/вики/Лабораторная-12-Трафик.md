## Цель эксперимента

В этой работе мы наблюдаем внутреннюю структуру соединения Tor **при наличии ключей собственной сессии TLS**. Сначала с помощью `tcpdump` записываем собственный трафик. Затем учебный клиент Python экспортирует ключи через `SSLKEYLOGFILE`, а `tshark` расшифровывает запись. После этого можно восстановить ячейки Tor и порядок их передачи внутри канала.

Мы расшифровываем **только собственный трафик** с разрешения участника соединения; перехват чужих ключей или данных не требуется.

## Подготовка

Команды выполняются из корня репозитория; используется только **частная лабораторная сеть**. При первом запуске нужно собрать образ. Одновременно запускать сети разных языковых изданий нельзя: порты на хосте совпадают.

```bash
# Только при первом запуске: make -C labs/ru/лаборатория image
make -C labs/ru/лаборатория start
export PYTHONPATH=labs/ru/код
```

**Внимание:** скрипт заменяет файлы предыдущего эксперимента `labs/ru/лаборатория/net/capture.pcap` и `keys.log`. Если результаты нужны, сохраните копии заранее. **Не публикуйте и не передавайте файл ключей TLS**: его содержимое позволяет расшифровать соответствующий сетевой сеанс. Каталог `labs/ru/лаборатория` монтируется в контейнер как `/lab`, а не как `/labs/ru/лаборатория`.

## Выполнение

Пример сначала запускает захват пакетов на порту локального ретранслятора `004r`, затем открывает тестовый канал, экспортирует ключи и перебирает распознанные потоки TLS. Команды `tshark` используют `-d tcp.port==5104,tls`, поскольку нестандартный порт 5104 не всегда автоматически распознаётся как TLS.

```bash
python3 - <<'PY'
import os, subprocess, time
from torlab.cells import CellCommand as C
from torlab.circuit import build
from torlab.laboratory import relay, NODES
from torlab.traffic import cells_from_follow as parse

network = "torbook-network"
keys = NODES.parent / "keys.log"
capture = NODES.parent / "capture.pcap"
# Файлы эксперимента временные: предыдущие версии будут перезаписаны.
keys.unlink(missing_ok=True)
capture.unlink(missing_ok=True)

# 1. захватить трафик только локального порта 5104
subprocess.run(["docker", "exec", "-u", "0", "-d", network, "sh", "-c",
                "timeout 12 tcpdump -i lo -w /lab/net/capture.pcap 'tcp port 5104'"],
               check=True)
time.sleep(2)

# 2. создать приватный канал и экспортировать ключи TLS
previous = os.environ.get("SSLKEYLOGFILE")
os.environ["SSLKEYLOGFILE"] = str(keys)
try:
    circuit = build([relay("004r")], cc=False)
    circuit.channel.sock.close()
finally:
    if previous is None:
        os.environ.pop("SSLKEYLOGFILE", None)
    else:
        os.environ["SSLKEYLOGFILE"] = previous
# Перед запуском tshark дождаться завершения захвата пакетов.
time.sleep(12)
if not keys.exists() or not keys.stat().st_size:
    raise RuntimeError("Ключи сеанса TLS не экспортированы")
keys.chmod(0o600)
print("Строк в файле ключей TLS:", len(keys.read_text().splitlines()))

# 3. найти потоки TCP с TLS и восстановить ячейки Tor
opts = ["-r", "/lab/net/capture.pcap", "-d", "tcp.port==5104,tls",
        "-o", "tls.keylog_file:/lab/net/keys.log"]
scan = subprocess.run(["docker", "exec", network, "tshark", *opts,
                       "-Y", "tls && tcp.port==5104", "-T", "fields", "-e", "tcp.stream"],
                      check=True, capture_output=True, text=True)
stream_ids = sorted({int(v) for v in scan.stdout.split() if v.isdigit()})
found = False
for stream_id in stream_ids:
    result = subprocess.run(["docker", "exec", network, "tshark", *opts,
                             "-q", "-z", f"follow,tls,raw,{stream_id}"],
                            check=True, capture_output=True, text=True)
    try:
        cells = parse(result.stdout)
        names = [(direction, C(cell.command).name)
                 for direction, cell, _ in cells]
    except (ValueError, IndexError):
        continue
    if len(names) >= 2 and [name for _, name in names[:2]] == ["VERSIONS", "VERSIONS"] \
            and "CREATED2" in [name for _, name in names]:
        print(f"поток {stream_id}:")
        for direction, cell, version in cells:
            print(f"  {direction} {C(cell.command).name} (тело {len(cell.body)} byte)")
        found = True
        break
if not found:
    raise RuntimeError("Последовательность VERSIONS / CREATED2 не найдена: проверьте pcap и ключи")
PY
```

## Исторический пример вывода (не гарантируется)

```text
TLS keys exported: 6 lines
flow 1:
   client VERSIONS (body 4 byte)
   relay VERSIONS (body 6 byte)
   relay CERTS (body 1446 byte)
   relay AUTH_CHALLENGE (body 36 byte)
   relay NETINFO (body 509 byte)
   client NETINFO (body 509 byte)
   client CREATE2 (body 509 byte)
   relay CREATED2 (body 509 byte)
```

Это **исторический вывод исходной среды**, сохранённый для сравнения: текущий русскоязычный пример печатает русские подписи. Номер потока, количество строк в журнале и длина сертификатов могут изменяться. В файле ключей возможны также строки комментариев.

Пояснения:

- Это тот же обмен сообщениями, что и в [лабораторной работе 1](Лабораторная-01-Канал.md), но ячейки восстановлены из расшифрованной записи TLS.
- Номер потока заранее неизвестен: сетевой интерфейс `lo` используется и другими соединениями. Обновлённый пример рассматривает **все индексы TCP-потоков**, которые `tshark` распознал как TLS на порту 5104, а затем ищет последовательность из двух `VERSIONS` и `CREATED2`. Если она отсутствует, выполнение завершается ошибкой; прежнее ограничение первыми восемью индексами снято.
- У ячеек фиксированной длины `NETINFO`, `CREATE2` и `CREATED2` тело дополняется до **509 байт**. Для протокола связи v4/v5 **полный размер такой ячейки — 514 байт** (4 байта CircID, 1 байт команды, 509 байт тела). Ячейки `VERSIONS` и `CERTS` имеют переменную длину.
- Шесть строк ключевого журнала в исходном примере **не являются постоянным значением**: число и состав записей зависят от версии TLS, реализации и сеанса. Ключи экспортируются библиотекой Python с помощью `ssl.SSLContext.keylog_filename`.

## Что видно без ключей?

Наблюдатель видит IP-адрес и порт тестового ретранслятора, TLS-соединение (в исторической записи использовался TLS 1.3), размеры пакетов и временные интервалы. В этой работе задействована исключительно **частная сеть**, а не публичные ретрансляторы Tor. Без ключей нельзя прочитать команды ячеек, их CircID и непосредственно узнать, сколько логических цепочек передаётся внутри зашифрованного канала.

Размеры пакетов и задержки всё же могут помочь при анализе корреляции трафика на обоих концах соединения; это рассматривается с защитной точки зрения в [лабораторной работе 16](Лабораторная-16-Корреляция.md).

## Автоматическая проверка

Проверка `lab12` находится в **итальянском** `scripts/verify_labs.py`. Она ищет две первые ячейки `VERSIONS` и последующую `CREATED2`, но историческая реализация рассматривает лишь первые восемь индексов потоков и не во всех случаях проверяет ошибки внешних команд. Пример в этой странице перебирает обнаруженные потоки и сообщает об отсутствии полной последовательности. Команда `make -C labs/ru/лаборатория verify` вызывает только проверку сети Chutney.

## Возможные проблемы

| Симптом | Что проверить |
|---|---|
| Ячейки не обнаружены ни в одном потоке | Экспортированы ли ключи до открытия TLS-сокета, верно ли декодируется порт 5104 как TLS, попало ли в запись начало обмена. |
| `tshark` не открывает файл захвата | Путь внутри контейнера — `/lab/net/capture.pcap`, проверьте права; для запуска `tcpdump` пример использует `docker exec -u 0`. |
| Файл захвата пуст | Запускайте `tcpdump` до открытия канала, оставляя короткую паузу. |
| Расшифрована только часть обмена | Запись могла завершиться слишком рано или быть неполной; увеличьте время захвата и проверьте файл ключей. |
| Нет TLS-потоков для анализа | Проверьте правильность `tcpdump`, возможность распознать TLS на порту 5104 и вывод команд `tshark`. |

**Ограничение:** запуск Docker, сборка и проверка реального захвата откладываются. Журнал ключей предназначен исключительно для контролируемого локального опыта.
