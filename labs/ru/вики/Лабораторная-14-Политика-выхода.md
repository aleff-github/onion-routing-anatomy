## Цель эксперимента

Через один и тот же выходной узел `006e` выполняются три попытки открыть поток на **127.0.0.1**: к адресу и порту, явно запрещённым **политикой выхода**, к разрешённому порту с работающим сервером и к разрешённому порту без сервера. Клиент получает `RELAY_END` с причиной отказа или `RELAY_CONNECTED`.

Все запросы остаются в **одноразовой сети Chutney**. Маршрут состоит из трёх узлов: `003r → 005r → 006e`. Публичные выходные ретрансляторы не используются.

## Подготовка

Запустите команды из корня репозитория. Перед первым использованием соберите образ. Разные языковые сети нельзя запускать одновременно: они используют одни и те же порты хоста.

```bash
# Только при первом запуске: make -C labs/ru/лаборатория image
make -C labs/ru/лаборатория start
export PYTHONPATH=labs/ru/код
```

Скрипт проверяет, что на порту `9999` нет сервера, открывает тестовый HTTP-сервер на `8081` и при возможности ещё один на `8080`. Затем временно добавляет строку `ExitPolicy reject 127.0.0.1:8080` **перед первой директивой `ExitPolicy`**, поскольку действует первое совпавшее правило. Это запрет **конкретной пары адрес–порт**, а не порта 8080 для всех адресов. Для перезагрузки только узла `006e` проверяются его PID из `/lab/net/nodes/006e/pid` и командная строка; широкая команда `pkill -f` не используется.

## Исторический пример вывода (не гарантируется)

```text
127.0.0.1:8080 -> END причина=EXITPOLICY адрес=127.0.0.1 TTL=1800
127.0.0.1:8081 -> CONNECTED
127.0.0.1:9999 -> END причина=MISC
```

Теперь русская версия скрипта печатает русские подписи `причина` и `адрес`; имена команд `END`, `CONNECTED`, `EXITPOLICY` и `MISC` оставлены без перевода как значения протокола.

- **8080 — `EXITPOLICY`:** выходной узел отклоняет адрес и порт. В `RELAY_END` могут присутствовать IPv4/IPv6-адрес и **необязательное** значение TTL; `1800` приведено лишь из старой записи, а дополнительные данные могут отсутствовать.
- **8081 — `CONNECTED`:** создано TCP-соединение с локальным тестовым сервером; это **не означает**, что HTML-страница была загружена.
- **9999 — `MISC` в исторической записи:** на проверяемом порту никто не слушал. Tor также определяет отдельную причину `CONNECTREFUSED` для отказа удалённого хоста; учебный скрипт принимает **оба** варианта.

## Особенность Tor 0.4.9.13

В старом эксперименте с **tor 0.4.9.13** при закрытом порту наблюдался `MISC` вместо ожидаемого `CONNECTREFUSED`. Прежний анализ исходного кода связывал это с повторным чтением `tor_socket_errno`: `getsockopt(SO_ERROR)` уже выдал `ECONNREFUSED`, однако позднее `errno` содержал `EINPROGRESS`, и выбиралась общая причина.

Это **историческая гипотеза на основании анализа конкретной версии**, а не повторная независимая проверка C-кода Tor. При ином результате следует изучить работающую версию и журналы узла. Спецификация различает `MISC` (1), `CONNECTREFUSED` (3) и `EXITPOLICY` (4).

## Почему три узла?

В прежнем одноузловом эксперименте возвращался `END TORPROTOCOL`. Спецификация рекомендует отказывать в запросах открытия внешних потоков через одноузловые цепочки, но **не гарантирует именно такую строку причины**: реализация может, например, уничтожить цепочку. Три узла позволяют отдельно исследовать политику выхода.

## Безопасность, восстановление и проверка

Ранее в русском скрипте подстановка через регулярное выражение могла ошибочно интерпретировать `\1` как управляющий символ при изменении `torrc`. Теперь вставка выполняется **срезами строки**, без таких обратных ссылок. Скрипт не добавляет уже существующее правило, контролирует занятость портов, закрывает сокеты и собственные серверы. В блоке `finally` он пытается восстановить исходный `torrc` и перезагрузить `006e`. **Если повторная загрузка не удалась, сообщается об ошибке**: восстановленный файл не доказывает, что Tor принял настройки. При аварийном завершении может понадобиться ручная проверка сети.

Итальянский проверяющий модуль `scripts/verify_labs.py::lab14` всё ещё требует строго прежние строки, включая `TTL=1800` и `MISC`, поэтому возможен **ложный отрицательный результат**. Обновлённый скрипт проверяет категории: запрет политикой, успешное TCP-соединение, отсутствие сервера (`MISC` или `CONNECTREFUSED`).

| Признак | Что проверить |
|---|---|
| Все попытки завершаются `TORPROTOCOL` | Убедиться, что цепочка трёхузловая; один узел — лишь одна из возможных причин. |
| Не удалось открыть поток на `8081` | Проверить локальный сервер, правила выхода и другие настройки; при занятом порту программа останавливается. |
| На порту `9999` не происходит отказа | Возможно, порт занят другим процессом; перед опытом программа проверяет его. |
| Не удалась перезагрузка после восстановления | Проверить PID `006e`, журналы и реально действующую конфигурацию, не отправляя сигналы посторонним процессам. |

Источники: [Tor Specifications — Closing streams](https://spec.torproject.org/tor-spec/closing-streams.html); [Opening streams](https://spec.torproject.org/tor-spec/opening-streams.html).
