## Что демонстрирует эта работа

**Границы применимости:** это упрощённая статистическая модель, **а не полный алгоритм Tor**. Она не учитывает семейства ретрансляторов, разрешённые порты конкретного назначения, весь механизм постоянных guard, подсети IPv6 и конфигурационные исключения. Вывод `probabilities()` — исходные доли весов кандидатов **до** применения исключений, а не итоговая вероятность выбора в готовую цепь.

Три ретранслятора цепи Tor не выбираются равномерно и независимо. Базовая вероятность выбора зависит от пропускной способности и веса, определяемого типом узла (guard, exit, оба флага или ни одного) и его позицией. Затем проверяются ограничения: разные идентификаторы ретрансляторов, разные IPv4-сети /16, guard в начале и exit в конце цепи.

Лабораторная работа анализирует **архивный консенсус публичной сети**, а не небольшую частную сеть: восемь сохранённых тестовых ретрансляторов непригодны для изучения общесетевых пропорций.

Как интерпретировать результат:

- Буквы описывают типы узлов: `g` — только Guard, `e` — только Exit, `d` — одновременно Guard и Exit, `m` — ни тот ни другой. Например, `gge` означает Guard в начале, ещё один Guard посередине и Exit в конце.
- В историческом снимке ретрансляторы с Exit не попадают на первые две позиции из-за нулевых весов соответствующих типов. Это отражает стремление сохранить дефицитную пропускную способность выходных узлов.

- В этом снимке концентрация сравнительно невелика: десять выходных ретрансляторов с наибольшими весами составляют небольшую часть суммарной вероятности выбора. Преобладание нескольких ретрансляторов увеличило бы риски централизованного наблюдения.

# Подробности реализации

В `labs/ru/код/torlab/path_selection.py` около 105 строк: они демонстрируют ограничения выбора пути из path-spec и позиционные веса из dir-spec.

## Тип ретранслятора

```python
def _relay_type(r: RelayEntry) -> str:
    """g = только Guard, e = только Exit, d = Guard и Exit одновременно, m = ни один."""
    g, e = "Guard" in r.flag, "Exit" in r.flag and "BadExit" not in r.flag
    return {(True, True): "d", (True, False): "g", (False, True): "e", (False, False): "m"}[(g, e)]
```

Флаг `BadExit` учитывается при определении пригодности выходного узла. Ретранслятор может иметь флаг `Exit`, но одновременно получить `BadExit` от властных узлов сети; тогда выбирать его выходом нельзя.

Буквы обозначают категории модуля: `d` — Guard и Exit, `g` — только Guard, `e` — только Exit, `m` — ни один из этих флагов.

## Вычисление веса

```python
def weight(r: RelayEntry, position: str, weights: dict[str, int], scale: int = 10000) -> float:
    """Применяет W<позиция><тип> с делением на bwweightscale консенсуса."""
    _check_position(position)
    _check_scale(scale)
    bw = r.bandwidth if r.bandwidth is not None else 0
    if isinstance(bw, bool) or not isinstance(bw, int) or bw < 0:
        raise ValueError("недопустимая пропускная способность ретранслятора")
    factor = weights.get(f"W{position[0]}{_relay_type(r)}", scale)
    if isinstance(factor, bool) or not isinstance(factor, int) or not 0 <= factor <= scale:
        raise ValueError("недопустимый вес пропускной способности консенсуса")
    return bw * factor / scale
```

Имя веса **формируется** из двух букв: первая кодирует позицию в цепи, вторая — тип ретранслятора. Например, `Wmg` — вес узла с флагом Guard при выборе среднего звена.

Существенные детали:

- Ретранслятор без объявленной пропускной способности получает нулевой вес; отрицательная или нецелая пропускная способность считается ошибкой консенсуса.
- Значение по умолчанию `scale` даёт полный вес, если ключ не указан.
- Деление на `scale` переводит целочисленные коэффициенты консенсуса в множитель от 0 до 1. Масштаб — параметр консенсуса `bwweightscale` (по умолчанию 10000), который `Selector` читает из параметров консенсуса.

В снимке от 23 сентября 2026 года некоторые веса для ретрансляторов с Exit на первых двух позициях были нулевыми, чтобы сохранять выходную пропускную способность.

## Почему веса вычисляются один раз

Ретрансляторы с нулевым весом исключаются из таблицы кандидатов `Selector`. При этом `probabilities()` сохраняет их в словаре с вероятностью ноль, поэтому количество «подходящих» не всегда совпадает с количеством реально выбираемых узлов.

```python
class Selector:
    """Для каждой позиции сохраняет подходящие ретрансляторы и их веса.

    Выбор среди допустимых альтернатив исключает ложный отказ при малом весе.
    """

    def __init__(self, consensus: Consensus):
        self.scale = consensus.parameters.get("bwweightscale", 10000)
        _check_scale(self.scale)
        self.candidates, self.weights = {}, {}
        for pos in POSITIONS:
            candidates = [r for r in consensus.relay if eligible(r, pos)]
            values = [weight(r, pos, consensus.weights, self.scale) for r in candidates]
            self.candidates[pos] = [r for r, w in zip(candidates, values) if w > 0]
            self.weights[pos] = [w for w in values if w > 0]
```

В ранней версии отбор более девяти тысяч ретрансляторов и вычисление весов выполнялись **при каждом выборе**: 2 000 путей занимали около 310 секунд. Предварительный расчёт списков кандидатов и весов делает моделирование практичным.

Ретрансляторы с нулевым эффективным весом сразу исключаются из списка для генератора; иначе они никогда не были бы выбраны.

## Ограничения через выборку с отбрасыванием

Ограничение `/16` в учебной модели относится только к IPv4. Реальная проверка подсетей настраивается и также применяется к IPv6 (обычно `/32`); для части onion-цепей бывают исключения.

```python
    def choose(self, pos: str, excluded: list[RelayEntry], rng: random.Random,
               distinct_networks: bool = True, attempts: int = 1000) -> RelayEntry:
        """Выбирает из допустимых узлов; параметр attempts оставлен для совместимости."""
        _check_position(pos)
        if isinstance(attempts, bool) or not isinstance(attempts, int) or attempts <= 0:
            raise ValueError("число попыток должно быть положительным")
        excluded_ids = {r.id_rsa for r in excluded}
        excluded_nets = {network16(r) for r in excluded} if distinct_networks else set()
        pairs = [(r, w) for r, w in zip(self.candidates[pos], self.weights[pos])
                 if r.id_rsa not in excluded_ids
                 and (not distinct_networks or network16(r) not in excluded_nets)]
        if not pairs:
            raise LookupError(f"нет подходящего ретранслятора для позиции {pos}")
        return rng.choices([r for r, _ in pairs], weights=[w for _, w in pairs])[0]
```

Ограничения применяются **отбрасыванием недопустимых выборок** вместо повторного фильтрования всего списка кандидатов. На большой сети такой подход обычно экономит вычисления.

Число попыток ограничено 1000, потому что в маленькой сети отбрасывание может затянуться: если почти все кандидаты находятся в одной сети /16, допустимые выборки редки. Когда попытки исчерпаны, `choose` отбирает только совместимые ретрансляторы и выбирает среди них; если таких нет, выдаётся понятное исключение, а программа не зависает.

Два ретранслятора считаются одним и тем же, если у них одинаковая RSA-идентичность, а не если это один и тот же Python-объект.

> **Псевдонимы не уникальны.** В исходном публичном снимке 151 псевдоним повторялся у разных ретрансляторов. Сравнение имён вместо идентификаторов может незаметно нарушить ограничения.

## Порядок выбора

```python
    def path(self, rng: random.Random, guard: RelayEntry | None = None,
             distinct_networks: bool = True) -> tuple[RelayEntry, RelayEntry, RelayEntry]:
        """Сначала Exit, затем допустимый Guard и в конце промежуточный узел."""
        if guard is not None:
            guard = next((r for r in self.candidates["guard"]
                          if r.id_rsa == guard.id_rsa), None)
            if guard is None:
                raise LookupError("фиксированный Guard отсутствует среди допустимых узлов консенсуса")
        e = self.choose("exit", [guard] if guard is not None else [], rng, distinct_networks)
        g = guard if guard is not None else self.choose("guard", [e], rng, distinct_networks)
        m = self.choose("middle", [e, g], rng, distinct_networks)
        return g, m, e
```

Сначала выбирается **выход**, затем guard, затем средний узел. Это обоснованно: выход наиболее ограничен правилами доступа к назначению. Если выбирать его последним, ранее выбранные узлы могут помешать построению совместимого пути.

Необязательный аргумент `guard` позволяет закрепить первый узел. [Лабораторная работа 19](Лабораторная-19-Моделирование.md) применяет его для моделирования постоянных guard. Закреплённый guard сначала ищется среди пригодных кандидатов консенсуса (`LookupError`, если его нет), а затем exit выбирается с его исключением по идентичности и по сети /16, так что ограничения выполняются и в этом случае.

## Что модель сознательно не включает

**Границы применимости:** это упрощённая статистическая модель, **а не полный алгоритм Tor**. Она не учитывает семейства ретрансляторов, разрешённые порты конкретного назначения, весь механизм постоянных guard, подсети IPv6 и конфигурационные исключения. Вывод `probabilities()` — исходные доли весов кандидатов **до** применения исключений, а не итоговая вероятность выбора в готовую цепь.

Модуль реализует только основные ограничения, а не весь механизм выбора маршрута. Намеренно отсутствуют:

- **семейства ретрансляторов**, сведения о которых доступны в микродескрипторах и оставлены читателю как упражнение;
- выбор постоянных guard с отфильтрованными, подтверждёнными и основными кандидатами;
- защитные Vanguards для onion-сервисов;
- изоляция потоков и предпочтения портов.

Полная производственная модель была бы реалистичнее, но скрыла бы влияние отдельных параметров на результат.
