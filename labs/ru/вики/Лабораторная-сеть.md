# Лабораторная сеть

Полноценная сеть Tor с центрами каталогов, ретрансляторами и onion-сервисом использует локальный адрес `127.0.0.1` внутри контейнера Docker. **Важно:** Makefile запускает контейнер с `--network host`, поэтому тот **использует сетевой стек хоста** и не обеспечивает независимую сетевую изоляцию. Эту частную топологию использует почти каждая лабораторная работа; подробности — в главе 19.

## Зачем запускать собственную сеть?

Экспериментировать в публичной сети Tor не следует. Отправленные туда пакеты проходят через ретрансляторы добровольцев рядом с трафиком людей, которые могут зависеть от Tor ради собственной безопасности. Действие, которое является безобидным однострочным экспериментом в приватной сети, в публичной сети может стать атакой на посторонних пользователей.

В собственной сети допустимы эксперименты, которые были бы неуместны где-либо ещё: намеренно испортить код аутентичности сообщения (MAC), чтобы проверить реакцию ретранслятора, превысить лимит `RELAY_EARLY`, изучить защиту от DoS, расшифровать собственную сессию TLS и последовательно исследовать её ячейки.

## Топология

Десять узлов, все на `127.0.0.1`:

| Узел | Роль | ORPort | ControlPort | Дополнительно |
|---|---|---:|---:|---|
| `000a`, `001a`, `002a` | Центр каталогов и ретранслятор | 5100–5102 | 8000–8002 | DirPort 7100–7102 |
| `003r`, `004r`, `005r` | Промежуточный ретранслятор | 5103–5105 | 8003–8005 | |
| `006e`, `007e` | Выходной ретранслятор | 5106, 5107 | 8006, 8007 | Выход к `127.0.0.0/8` |
| `008c` | Клиент | — | 8008 | SocksPort 9008 |
| `009h` | v3 onion-сервис | — | 8009 | Виртуальный порт 5858 → `127.0.0.1:4747` |

**Правило портов:** узел *n* использует ORPort `5100+n`, ControlPort `8000+n`, а клиент — SocksPort `9000+n`. Это правило действует во всей сети и всех лабораторных работах: `5103` всегда принадлежит `003r`, а `9008` — клиенту.

Chutney называет узлы `test000a`, `test003r` и т. д. В книге и wiki часто используются сокращённые имена.

При интерпретации результатов важно помнить о трёх отличиях от публичной сети:

- Центры каталогов голосуют **каждые 20 секунд**, а не раз в час; это позволяет быстрее получать новый консенсус в контролируемой сети.
- Промежуточных ретрансляторов всего три, поэтому ограничения разнообразия маршрутов — разные узлы, разные сети /16 и семейства ретрансляторов — здесь нельзя наблюдать в условиях, сравнимых с публичной сетью. [Лабораторная работа 7](Лабораторная-07-Маршруты.md) исследует это на публичном консенсусе.
- Все узлы используют один IP-адрес, поэтому некоторые защиты по конструкции становятся неэффективными.

Альтернативная топология `book-bridge` **не является обычной сетью плюс три узла**: в её конфигурации Chutney **12 узлов** (три обычных центра каталогов, один центр каталогов мостов, три промежуточных ретранслятора, два выхода, один мост obfs4 и два клиента, включая клиент моста). В ней **нет onion-сервиса `009h`**. Она предназначена для [лабораторной работы 10](Лабораторная-10-Мост.md); для экспериментов с onion-сервисом нужно вернуться к `book`.

## Команды

**Требования и ограничения изоляции:** необходимы Docker и GNU Make, а также подходящая среда Linux; при сборке образа Tor, Chutney и зависимости скачиваются через Интернет. Docker использует **сетевой режим хоста**: порты частной сети доступны на том же хосте и совпадают у всех языковых изданий. **Нельзя запускать две языковые сети одновременно.** EN/RU/ZH-CN также используют одни и те же имена образа и контейнера (`torbook-lab:latest`, `torbook-network`), хотя ES и IT имеют собственные имена. До запуска убедитесь, что другие экземпляры остановлены.

Из корня репозитория:

```bash
make -C labs/ru/лаборатория image       # один раз: собрать image русской лабораторной среды
make -C labs/ru/лаборатория start       # создать контейнер и узлы; дождаться bootstrap
make -C labs/ru/лаборатория verify      # сквозная проверка Chutney
make -C labs/ru/лаборатория status      # показать состояние узлов
make -C labs/ru/лаборатория shell       # открыть shell внутри контейнера
make -C labs/ru/лаборатория stop        # остановить узлы и удалить контейнер; сохранить net/
make -C labs/ru/лаборатория clean       # также удалить labs/ru/лаборатория/net/

PYTHONPATH=labs/ru/код python3 -m pytest -q labs/ru/код/torlab/test
```

Для bridge-топологии лабораторной работы 10:

```bash
make -C labs/ru/лаборатория clean
make -C labs/ru/лаборатория start NETWORK=book-bridge
make -C labs/ru/лаборатория verify
```

Завершите работу моста и снова создайте обычную топологию `book`. Команда `clean` **удаляет весь каталог `labs/ru/лаборатория/net/`**, включая временные закрытые ключи, идентификаторы onion-сервисов и состояние; при следующем запуске идентификаторы поменяются. Цель `verify` проверяет активную сеть Chutney, а не весь набор тестов Python. Русская среда не зависит от Makefile-целей других языковых изданий.

## Расположение файлов

```text
labs/ru/лаборатория/net/nodes/            десять узлов (symlink на nodes.<timestamp>)
labs/ru/лаборатория/net/nodes/003r/
    torrc                 конфигурация, сгенерированная Chutney
    fingerprint           отпечаток идентификатора RSA
    fingerprint-ed25519   идентификатор Ed25519, проверяемый в лабораторных работах
    notice.log            первое место для диагностики проблем
    pid
labs/ru/лаборатория/net/nodes/008c/cached-microdescs.new    ntor-ключи relay глазами клиента
labs/ru/лаборатория/net/nodes/009h/hidden_service/hostname  адрес .onion сервиса
```

`labs/ru/лаборатория/net/` **не отслеживается системой контроля версий**. В нём находятся закрытые ключи — пусть и только игрушечной сети — и он создаётся заново после каждого `make -C labs/ru/лаборатория clean && make -C labs/ru/лаборатория start`. При каждой новой инициализации меняются идентификаторы узлов. Поэтому отпечатки в вашем выводе будут отличаться от приведённых в книге и wiki — это ожидаемо.

Модуль `torlab.laboratory` читает эти файлы за вас:

```python
from torlab.laboratory import relay
r = relay("003r")
print(r.port, r.id_ed.hex()[:16], r.ntor.hex()[:16])
```

## Правила безопасности

Лабораторные сценарии намеренно генерируют необычный трафик: некорректные ячейки, превышение ограничений, тестовые запросы и захваты пакетов. Запускайте их **только в этой приватной сети**. Использование таких сценариев против реальных relay или сервисов может навредить их пользователям и нарушать закон. Соответствующие правовые вопросы рассматриваются в главе 25.

Лабораторные работы 7, 15 и 19 изучают **архивные публичные документы** Tor Project из CollecTor, не посылая экспериментальный трафик ретрансляторам общедоступной сети или пользователям. Для первоначальной загрузки документов требуется **HTTPS и доступ в Интернет**.
