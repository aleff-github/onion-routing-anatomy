## Что демонстрирует эта работа

Одна из самых простых ошибок при ручной настройке приложений для Tor — позволить **самому приложению разрешить имя хоста локально**, вместо того чтобы передать имя хоста tor. Последующее TCP-соединение всё ещё может идти через Tor и создавать ощущение полной защиты, хотя разрешение имени могло раскрыть домен вне цепи Tor; внешний DNS-запрос не обязателен и не обязательно открыт.

Лаборатория также показывает, что tor умеет **распознавать этот признак риска**, если соответствующая диагностика включена.

## Подготовка

Работайте из корня репозитория. При первом запуске соберите образ с `make -C labs/ru/лаборатория image`. Не запускайте несколько языковых сетей одновременно: они используют одинаковые порты хоста.

```bash
make -C labs/ru/лаборатория start
```

Скрипт сам запускает локальный HTTP-сервер с фиксированным ответом, не публикующий файлы и выполняется внутри контейнера; через `stem` он получает сообщения с порта управления клиентом:

```bash
docker exec -w /tmp torbook-network python3 /lab/dns_leak.py
```

## Схематический исторический вывод (не гарантируется)

Программа печатает **три строки**, по одной для каждого опыта. Сообщения Tor обрезаются до 110 символов и могут отличаться между версиями; ниже приведены **условные фрагменты**, а не гарантированный дословный вывод:

```text
--socks5           HTTP 200  tor: ... only an IP address ...
--socks5-hostname  HTTP 200  tor: ... DNS resolution itself if necessary ...
--socks5 SafeSocks HTTP 000
```

Как читать результат:

- **`--socks5`** заставляет curl разрешить имя локально и передать tor **только IP-адрес**. В примере HTTP-запрос проходит успешно — именно поэтому ошибка легко остаётся незамеченной. `TestSocks 1`, временно включённый скриптом, позволяет tor сообщить о запросе только с IP-адресом; сам по себе такой запрос не доказывает утечку DNS.
- **`--socks5-hostname`** передаёт через SOCKS само **имя хоста**, позволяя выполнить разрешение на выходном узле. Это желаемый вариант.
- При **`SafeSocks 1`** tor уже не только предупреждает, а отклоняет запрос только с IP-адресом. curl показывает `000`, потому что HTTP-соединение не устанавливается.

Несколько символов в параметре командной строки меняют место разрешения имени. Это одна из причин, по которой обычному пользователю безопаснее применять Tor Browser, а не вручную настраивать произвольные приложения.

> **Важное ограничение.** Лаборатория намеренно использует `localhost`, который разрешается в адрес обратной петли без обращения к внешнему DNS-серверу. Во время эксперимента реальный DNS-запрос не покидает машину. Демонстрируется механизм: с `--socks5` приложение разрешает имя до обращения к tor, и tor получает только IP-адрес. Замена `localhost` обычным доменом могла бы вызвать внешний DNS-запрос, потенциально открытый, чего эта приватная лаборатория сознательно избегает.

## Три релевантные опции tor

| Опция | Эффект |
|---|---|
| `TestSocks 1` | Записывает, какую форму запроса SOCKS увидел tor. Только диагностика. |
| `SafeSocks 1` | Отклоняет запросы, где передан IP-адрес вместо имени хоста. |
| `WarnUnsafeSocks` | Выдаёт предупреждения; включена по умолчанию в исходной конфигурации. |

Ни одна из этих настроек не способна остановить DNS-запрос, который уже произошёл **до** обращения приложения к tor. Они могут реагировать только на ту форму запроса, которую в итоге получает tor. Скрипт использует `--noproxy ''`, чтобы переменная `NO_PROXY` не позволила обойти SOCKS для `localhost`.

**Безопасность и восстановление.** Обновлённая программа выдаёт только фиксированный текст на `127.0.0.1:8080`, а не содержимое рабочих каталогов. Если порт уже занят, она останавливается. Применяется `--noproxy ''` для принудительного использования SOCKS. Исходные значения `TestSocks` и `SafeSocks` сохраняются и восстанавливаются в `finally`, в том числе при ошибках; принудительное завершение может этому помешать. Проверяются и HTTP-код, и код завершения curl, и соответствующие уведомления Tor; иначе программа завершится с ошибкой. `localhost` обычно разрешается локально, но **скрипт не захватывает DNS-пакеты**, поэтому не доказывает абсолютное отсутствие сетевых запросов.

## Известные проблемы

| Симптом | Причина |
|---|---|
| Предупреждение не появляется | Скрипт мог не включить `TestSocks` через `SETCONF` на ControlPort. |
| Третий тест всё ещё возвращает `200` | `SafeSocks` не был успешно применён. |
| Все три теста возвращают `HTTP 000` | Возможно, не работает частная сеть или локальный тестовый сервер скрипта. |
