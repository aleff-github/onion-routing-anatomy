## Цель эксперимента

Onion-сервис версии 3 может требовать **авторизацию клиента по ключу X25519** для расшифровки внутреннего слоя своего дескриптора. Клиент без подходящего закрытого ключа не сможет извлечь из защищённого слоя сведения о точках введения и обычно не сможет соединиться с сервисом. При этом сам дескриптор может быть доступен на HSDir: **скачивание не означает возможность расшифровать его**. Ограничение действует до уровня входа в веб-приложение.

**Критически важное условие:** Tor активирует авторизацию лишь после успешной загрузки хотя бы одного корректного файла `.auth`. **Пустой** каталог `authorized_clients` **не обеспечивает защиту**: без включённой авторизации сервис может оказаться доступен каждому, кто знает его адрес. Ошибка `400 Invalid HS descriptor`, полученная в прежнем опыте, была частным наблюдением, а не гарантией для всех версий Tor.

## Подготовка

Команды выполняются из корня репозитория на **временной частной сети**. Сети языковых изданий используют одинаковые порты хоста, поэтому не запускайте их одновременно. При первом запуске соберите образ, затем запустите локальный HTTP-сервер:

```bash
# Только при первом запуске: make -C labs/ru/лаборатория image
make -C labs/ru/лаборатория start
python3 -m http.server 8080 --bind 127.0.0.1 &
export PYTHONPATH=labs/ru/код
```

Скрипт создаёт **второй** временный сервис в `009h/restricted_service`, не изменяя обычный onion-сервис. Перед записью он убеждается, что каталогов `restricted_service` и `onion_auth` и прежних указаний авторизации в `torrc` нет. Если такие данные уже существуют, программа **останавливается, ничего не удаляя**. Новые ключевые файлы получают ограниченные права доступа; при неудачной повторной загрузке Tor они сохраняются для ручной проверки.

## Исторический пример вывода (не гарантируется)

```text
сервис с ограниченным обнаружением: 4stlyhm3pkptxitznaip66qf3tnuhujabwq6louhibhds7lwk7qcoeyd.onion
без ключа: 000
с ключом: 200
```

Адрес вновь созданного сервиса, задержки и HTTP-ответы могут изменяться. **`000` означает, что curl не получил код ответа HTTP; это не доказательство отказа именно по причине отсутствия ключа.** Причиной могут быть также недоступность локального веб-сервера, ошибка SOCKS, задержка публикации или нарушение работы частной сети. **`200`** означает, что авторизованная попытка достигла учебного HTTP-сервера, но не объясняет автоматически причину отказа без ключа.

## Устройство авторизации

1. Создаётся новая пара ключей **X25519** и дополнительный временный onion-сервис на узле `009h`.
2. **Открытый** ключ записывается до перезагрузки в `<HiddenServiceDir>/authorized_clients/alice.auth` как `descriptor:x25519:<открытый-ключ-base32>`. Для включения защиты Tor должен загрузить хотя бы один корректный читаемый файл `.auth`.
3. Для клиента `008c` задаётся `ClientOnionAuthDir`; при второй попытке **закрытый** ключ помещается в `alice.auth_private` в формате `<адрес-без-.onion>:descriptor:x25519:<закрытый-ключ-base32>`.
4. Сигнал HUP отправляется только целевому процессу Tor после проверки PID узла и его командной строки. Сначала запрос выполняется без ключа, затем с ключом, через локальный SOCKS-прокси, без обхода из-за `NO_PROXY`.
5. В блоке `finally` восстанавливаются оба исходных файла `torrc`, Tor повторно загружает их, после чего удаляются лишь каталоги, **созданные текущей попыткой**. При принудительном завершении вроде `SIGKILL` блок `finally` не выполняется: проверяйте состояние сети вручную.

Программа завершится с ошибкой, если вместо `000` без ключа или `200` с ключом появятся другие значения. Это **учебные условия проверки**, а не исчерпывающее доказательство правильной криптографической авторизации.

## Неисправности и восстановление

| Симптом | Что проверить |
|---|---|
| Обе попытки дают `000` | Работа HTTP-сервера на 8080, загрузка узлов, публикация дескриптора, SOCKS и журналы Tor. |
| Клиент завершает работу из-за `ClientOnionAuthDir` | Требуется путь **внутри контейнера**, полученный из `DataDirectory`, а не путь хоста. |
| Каталоги авторизации уже существуют | Программа не запускается. Проверить `torrc`, `restricted_service`, `onion_auth` **в одноразовой сети**; не удалять ключи без анализа. |
| Ошибка `400 Invalid HS descriptor` или сервис открывается без ключа | Проверить, загрузил ли Tor хотя бы один корректный `.auth`. Пустой каталог не доказывает активацию защиты. |
| Не удалось отправить HUP или восстановить настройки | Проверить PID нужного процесса, `torrc` и сохранённые временные ключи; не применять `pkill -HUP -f` или массовую очистку к рабочему серверу. |

## Автоматическая проверка и ограничения

Функция `lab13` в **итальянском** файле `scripts/verify_labs.py` проверяет вывод `000` и `200`, но не причину отсутствия HTTP-ответа и не все криптографические условия. Русскоязычный скрипт завершает работу с ошибкой, если наблюдения отличаются. `make -C labs/ru/лаборатория verify` выполняет проверку сети Chutney, а не итальянский `lab13`.
