## Что демонстрирует эта работа

Приватная сеть книги — не «сеть для C-реализации tor», а сеть **протокола Tor**. Отдельная реализация может присоединиться к ней, загрузить документы каталога, построить цепи и передавать трафик через ретрансляторы на C, при этом ретрансляторам не требуется знать, какой реализацией пользуется клиент.

Это сильное свидетельство того, что форматы, изученные в книге, являются совместимыми между реализациями форматами протокола, а не внутренними соглашениями одной реализации.

## Подготовка

Соберите исторически зафиксированную версию Arti 2.6.0 **только для воспроизведения эксперимента в контролируемой частной сети**. Не следует рекомендовать эту старую версию для работы в общедоступной сети Tor: последующие выпуски, включая Arti 2.7.0 (октябрь 2026 года), содержат исправления безопасности. Исходный код доступен в репозитории Tor Project:

```bash
mkdir -p labs/ru/vendor
git clone https://gitlab.torproject.org/tpo/core/arti.git labs/ru/vendor/arti
git -C labs/ru/vendor/arti checkout arti-v2.6.0
(cd labs/ru/vendor/arti && cargo build --release -p arti --locked)
```

Сгенерируйте конфигурацию для приватной сети:

```bash
export PYTHONPATH=labs/ru/код
python3 labs/ru/лаборатория/arti_config.py
```

Скрипт читает идентификаторы и порты центров каталогов из файлов приватной сети и записывает `labs/ru/лаборатория/net/arti/arti.toml`. Он воспроизводит настройки, необходимые именно лабораторной среде: частные центры каталогов и резервные кеши, локальные адреса, отключённое ограничение разнообразия подсетей потому что все узлы находятся на адресах обратной петли, а также сокращённый период HSDir.

## Запуск эксперимента

Запустите команды из корня репозитория в POSIX-оболочке после запуска частной сети командой `make -C labs/ru/лаборатория start` (если сеть уже работает, запускать её повторно не нужно). Проверяются **и** код HTTP, **и** фиксированный текст ответа, поэтому посторонний сервер на порту 8080 не будет принят за тестовый. Сервер не публикует файлы текущего каталога.

```sh
(
set -eu
ARTI_BIN="labs/ru/vendor/arti/target/release/arti"
ARTI_CFG="labs/ru/лаборатория/net/arti/arti.toml"
ARTI_LOG="labs/ru/лаборатория/net/arti/arti.log"
HTTP_LOG="labs/ru/лаборатория/net/arti/http.log"
ARTI_PID=
HTTP_PID=
BODY_FILE=

cleanup() {
  if [ -n "$HTTP_PID" ]; then
    kill "$HTTP_PID" 2>/dev/null || true
    wait "$HTTP_PID" 2>/dev/null || true
  fi
  if [ -n "$ARTI_PID" ]; then
    kill "$ARTI_PID" 2>/dev/null || true
    wait "$ARTI_PID" 2>/dev/null || true
  fi
  if [ -n "$BODY_FILE" ]; then rm -f "$BODY_FILE"; fi
}
trap cleanup EXIT
trap 'exit 130' INT
trap 'exit 143' TERM
trap 'exit 129' HUP

[ -x "$ARTI_BIN" ] && [ -f "$ARTI_CFG" ] || {
  echo "Не найден исполняемый файл Arti или конфигурация частной сети" >&2
  exit 1
}
: > "$ARTI_LOG"
"$ARTI_BIN" proxy -c "$ARTI_CFG" > "$ARTI_LOG" 2>&1 &
ARTI_PID=$!

# Дождаться запуска именно этого процесса Arti
ready=0
n=0
while [ "$n" -lt 60 ]; do
  if grep -q "proxy now functional" "$ARTI_LOG" && kill -0 "$ARTI_PID" 2>/dev/null; then
    ready=1
    break
  fi
  if ! kill -0 "$ARTI_PID" 2>/dev/null; then
    echo "Arti завершился до начальной загрузки; проверьте $ARTI_LOG" >&2
    exit 1
  fi
  n=$((n + 1))
  sleep 2
done
[ "$ready" -eq 1 ] || {
  echo "Arti не завершил начальную загрузку; проверьте $ARTI_LOG" >&2
  exit 1
}

# Локальный HTTP-сервер: фиксированный ответ только для /
python3 -u - > "$HTTP_LOG" 2>&1 <<'PY' &
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path != "/":
            self.send_error(404)
            return
        body = b"arti-private-lab-ok\n"
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, *_args):
        pass

ThreadingHTTPServer(("127.0.0.1", 8080), Handler).serve_forever()
PY
HTTP_PID=$!
sleep 1
kill -0 "$HTTP_PID" 2>/dev/null || {
  echo "Локальный HTTP-сервер не запустился; проверьте $HTTP_LOG" >&2
  exit 1
}

BODY_FILE=$(mktemp)
HTTP_CODE=$(curl --fail --silent --show-error --max-time 30 \
  --noproxy "" --socks5-hostname 127.0.0.1:9150 \
  -o "$BODY_FILE" -w '%{http_code}' http://127.0.0.1:8080/)
[ "$HTTP_CODE" = "200" ] && [ "$(cat "$BODY_FILE")" = "arti-private-lab-ok" ] || {
  echo "Неожиданный HTTP-ответ из частной лабораторной сети" >&2
  exit 1
}
printf '%s\n' "$HTTP_CODE"
)
```

Сценарий очищает старый журнал, проверяет, что запущенный им Arti продолжает работать, завершает проверку при занятом порту 8080 и останавливает **только созданные им процессы** даже при обрабатываемых ошибках и сигналах. Не используйте `pkill` для завершения чужих процессов. Код `200` принимается **только при совпадении** тела ответа `arti-private-lab-ok` и успешном завершении curl. Проверяется доступность локального сервера через выходные узлы **частной сети**, а не через общедоступную сеть Tor.

## Исторический пример вывода

```text
2026-09-24T16:05:45Z  INFO arti::subcommands::proxy: Sufficiently bootstrapped; proxy now functional.
200
```

Как интерпретировать результат:

- Arti загрузил и проверил документы каталогов частных центров, завершил начальную загрузку, построил цепь и передал HTTP-запрос через ту же сеть ретрансляторов. Ретрансляторам не нужны сведения о реализации клиента.
- Пустой параметр `--noproxy ""` гарантирует обращение через SOCKS даже к `127.0.0.1`, несмотря на переменные `NO_PROXY`/`no_proxy`. Журнал и ответ HTTP ниже являются историческим примером, а не новым тестом.
- Стандартный порт SOCKS Arti в этой конфигурации — **9150**, что соответствует соглашению Tor Browser, а не стандартному порту 9050 у отдельного процесса tor.

## Чем Arti отличается от tor

Arti использует конфигурацию TOML вместо `torrc`. Записи частных центров каталогов содержат поля вроде `rsa_identity`, `ed_identity` и `orports`, то есть содержат идентификаторы старого формата и Ed25519.

Глава 30 подробнее рассматривает поддерживаемые функции Arti и намеренно отсутствующие роли, включая то, что роль ретранслятора пока разрабатывается отдельно.

Следует отметить одно исправление документации: таблица версий в Arti `Compatibility.md` была смещена на единицу для `FlowCtrl` относительно torspec. Спецификация и данные публичного консенсуса (`FlowCtrl=1-2`) показывают, что 1 — это `AUTH_SENDME`, а 2 — управление перегрузкой. Когда документация реализации расходится со спецификацией протокола, нужно проверить спецификацию и данные сети.

## Автоматическая проверка

Итальянский эталонный проверяющий модуль `scripts/verify_labs.py::lab20` **не выполняет проверку этой локализованной инструкции**. Он использует исполняемый файл `fonti/arti/target/release/arti` и корневой генератор `лаборатория/arti_config.py`, тогда как в этом руководстве указаны пути `labs/ru/...`. Если корневой бинарный файл не найден, результат — **пропуск, а не успех**.

## Известные проблемы

| Симптом | Причина |
|---|---|
| `Lab 20: Arti binary not found; laboratory skipped` | Отсутствует `labs/ru/vendor/arti/target/release/arti`. |
| Bootstrap не завершается | Приватная сеть остановлена либо `arti.toml` был сгенерирован до последующей регенерации сети. Снова запустите `arti_config.py`. |
| `Permission denied` для каталогов состояния | Arti требует ограниченного доступа к файлам состояния. Удаляйте только одноразовое лабораторное состояние в `labs/ru/лаборатория/net/arti/state` и повторите. |
| `pkill -f "arti proxy"` или `pkill -x arti` завершает посторонние процессы | Не завершайте процессы по общему имени: приведённый сценарий отслеживает собственные PID и освобождает их через `trap`. |
