# Установка

Начинайте с этой страницы на машине, где репозиторий ещё не использовался.

## Требования

| | Для чего требуется | Как проверить |
|---|---|---|
| **Docker** | Запускает всю лабораторную сеть; также используется для сборки книги | `docker run --rm hello-world` |
| **Python 3.11+** | Учебный клиент `torlab` | `python3 --version` |
| **`cryptography`** | X25519, Ed25519 и AES | `python3 -c "import cryptography; print(cryptography.__version__)"` |
| **`pytest`** | Тесты Python, фактическое число уточняется при запуске | `python3 -m pytest --version` |
| **Rust (`cargo`)** | **Только** для лабораторной работы 20, где собирается Arti | `cargo --version` |

```bash
python3 -m pip install -r requirements.txt
```

Устанавливать `stem` на хост не требуется: три лабораторные работы, где он используется (11, 16 и 18), выполняются внутри контейнера, в котором он уже установлен.

Место на диске: около **3 GB** для образ Docker, исходного кода tor и состояния сети. Для лабораторной работы 20 требуется ещё примерно **2 GB** на компиляцию Arti.

Операционная система: среда разрабатывалась и проверялась на Linux. В macOS Docker работает внутри виртуальной машины; `--network host` ведёт себя иначе, чем в Linux, поэтому лабораторную сеть придётся адаптировать, а лабораторные работы с перехватом трафика через `lo` (10 и 12) не будут работать без изменений.

## Шаг 1: сборка image

```bash
make -C labs/ru/лаборатория image
```

Команда собирает tor 0.4.9.13 из исходного кода внутри образа вместе с Chutney, obfs4proxy, snowflake-client, `tshark` и `curl`. **Сборка занимает несколько минут** — в исходной тестовой среде без кэша около тринадцати минут — и загружает несколько сотен мегабайт.

Почему tor компилируется, а не устанавливается из пакета дистрибутива?

- Версия **зафиксирована** в Dockerfile (`ARG TOR_VERSION`), что сохраняет воспроизводимость результатов книги.
- Требуется `--enable-gpl`, включающий модуль proof of work для onion-сервисов (лабораторная работа 9, глава 15). Пакеты дистрибутивов могут быть собраны иначе, поэтому конфигурацию следует проверять, а не предполагать.
- Доступность исходного кода — часть замысла книги: если спецификация не отвечает на вопрос, можно исследовать реализацию в `src/core/or/`.

Проверка:

```bash
docker run --rm torbook-lab:latest tor --version
```

## Шаг 2: запуск сети

```bash
make -C labs/ru/лаборатория start
```

Команда создаёт контейнер `torbook-network`, генерирует ключи и конфигурацию десяти узлов через Chutney и ждёт завершения bootstrap. RU, EN и ZH-CN используют общие имена Docker и порты хоста: нельзя запускать несколько таких сред одновременно, а перед переключением следует остановить предыдущую. В исходной среде автора это занимало около двух минут: authorities приватной сети голосуют каждые 20 секунд, поэтому первый консенсус появляется быстро.

```bash
make -C labs/ru/лаборатория verify
```

Ожидаемый результат исходной проверенной среды: `successes:4 failures:0`. Chutney отправляет тестовый трафик через сеть и проверяет сквозную доставку.

При ошибках см. [Устранение неполадок](Устранение-неполадок.md).

## Шаг 3: проверка лабораторных работ

```bash
make -C labs/ru test          # тесты Python без сети
make -C labs/ru/лаборатория verify    # Chutney, после запуска сети
```

Тесты Python и проверки Chutney не заменяют все двадцать лабораторных экспериментов; инструкции по отдельным сценариям см. в [автоматической проверке](Автоматическая-проверка.md). Для работ 7, 15 и 19 нужны исторические данные консенсуса. Исходный показатель 53/53 не является новым результатом тестов. Корневой `make verify-labs` по умолчанию проверяет английское издание, поэтому здесь не подходит.

Тесты кода, не требующие лабораторной сети:

```bash
PYTHONPATH=labs/ru/код python3 -m pytest -q labs/ru/код/torlab/test
```

Числа выше описывают исходную проверенную среду. Они **не означают**, что во время перевода русского издания все тесты автоматически запускались заново.

## Шаг 4 (необязательно): сборка книги

Корневая команда `make book-pdf` собирает исходное итальянское издание. Для русского издания в полной рабочей копии используйте:

```bash
make -C source/ru pdf
```

LaTeX и шрифты должны соответствовать требованиям `docs/translations/ru.md`; финальный PDF русского издания должен пройти отдельную визуальную проверку.

## Остановка сети

```bash
make -C labs/ru/лаборатория stop     # остановить узлы, сохранив ключи и данные в labs/ru/лаборатория/net/
make -C labs/ru/лаборатория clean    # остановить сеть и удалить labs/ru/лаборатория/net/
```

`labs/ru/лаборатория/net/` содержит закрытые ключи тестовых узлов. Каталог не отслеживается системой контроля версий и не должен публиковаться. Эти ключи принадлежат игрушечной сети, но аккуратное обращение с ними помогает не выработать опасные привычки при работе с настоящими ключами.
