**Границы эксперимента:** девять успешных запросов из 30 — исторический результат конкретной версии Tor и времени испытания, а не неизменяемое правило. ## Часть 1 — Ограничения создания цепей

**До изменения конфигурации** убедитесь, что запущена только нужная частная сеть. Сигнал HUP направляется по PID конкретного узла внутри нужного контейнера, а не поиском имени процесса. `finally` восстанавливает файл, но при ошибке сигнала либо принудительном завершении требуется вручную сверить файл и журнал.

Эксперимент временно добавляет в `torrc` узла `003r` низкие пороги защиты от DoS, перезагружает конфигурацию узла, направляет 30 последовательных запросов `CREATE_FAST` и восстанавливает исходный файл в блоке `finally`.

```bash
python3 - <<'EOF'
import subprocess, time
from collections import Counter
from torlab.channel import open_channel
from torlab.cells import Cell, CellCommand
from torlab.laboratory import relay, NODES
from torlab.ntor import create_fast_client

torrc = NODES / "003r" / "torrc"
original = torrc.read_text()
hup = ["docker", "exec", "torbook-network", "sh", "-c",
       "kill -HUP $(cat /lab/net/nodes/003r/pid)"]
try:
    torrc.write_text(original + """
DoSCircuitCreationEnabled 1
DoSCircuitCreationMinConnections 2
DoSCircuitCreationRate 1
DoSCircuitCreationBurst 10
DoSCircuitCreationDefenseType 2
DoSCircuitCreationDefenseTimePeriod 60 seconds
""")
    subprocess.run(hup, check=True); time.sleep(2)
    g = relay("003r")
    for source, channel_count in (("127.0.0.2", 2), ("127.0.0.3", 1), ("127.0.0.1", 2)):
        channels = [open_channel("127.0.0.1", g.port, expected_identity=g.id_ed, source_address=source)
                  for _ in range(channel_count)]
        results, reasons, first_rejection = [], Counter(), None
        for i in range(30):
            x, body = create_fast_client()
            channels[0].send(Cell(0x80000100 + i, CellCommand.CREATE_FAST, body))
            r = channels[0].receive()
            while r.command in (CellCommand.PADDING, CellCommand.VPADDING):
                r = channels[0].receive()
            ok = r.command == CellCommand.CREATED_FAST
            results.append(ok)
            if not ok:
                reasons[r.body[0]] += 1
                first_rejection = first_rejection or i + 1
        m = ", ".join(f"DESTROY({k})" for k in reasons)
        print(f"источник {source}, каналов {channel_count}: принято {results.count(True)}, "
              f"отказов {30-results.count(True)} {m or '-'}; первый отказ: {first_rejection}")
finally:
    torrc.write_text(original)
    subprocess.run(hup)
EOF
```

```text
источник 127.0.0.2, каналов 2: принято 9, отказов 21 DESTROY(5); первый отказ: 10
источник 127.0.0.3, каналов 1: принято 30, отказов 0 -; первый отказ: None
источник 127.0.0.1, каналов 2: принято 9, отказов 21 DESTROY(5); первый отказ: 10
```

**Исторические иллюстративные значения:** точное число принятых запросов зависит от времени, пополнения жетонов и состояния защиты. Сверяйте коды реальных ответов, а не требуйте обязательно девять успешных запросов на любой машине.

Три важных наблюдения:

1. В историческом примере отказ имеет вид **`DESTROY` с причиной 5** — `RESOURCELIMIT`.
2. В исходной конфигурации при `DoSCircuitCreationBurst 10` было принято **9** запросов: при исчерпании жетонов клиента помечают, и десятый запрос отклоняется. Поведение может меняться из-за задержек и пополнения жетонов.
3. При **одном канале** установленный порог `DoSCircuitCreationMinConnections 2` ещё не достигнут, поэтому в этой конфигурации защита не срабатывала.

Исторический эксперимент показал, что для защиты от частого создания цепей в `dos.c` не существовало отдельного исключения для адреса loopback.

Разные локальные адреса источника нужны, чтобы испытания не разделяли уже помеченное состояние одного IP. Помеченный адрес остаётся ограниченным в течение настроенного периода защиты.

## Часть 2 — Доказательство работы onion-сервиса

Это настройка onion-сервиса, а не временный Python-тест. Сохраните копию исходного `torrc` узла `009h`, перезагрузите его по PID после изменения, а после опыта **восстановите оригинал и снова отправьте HUP**. Если восстановление не удалось, пересоздайте одноразовую частную сеть.

Строка `pow-params` — исторический пример. Её семя, время UTC и рекомендуемое усилие могут изменяться. Нулевое усилие означает, что в тот момент выполнение PoW не требовалось, но само по себе не доказывает отсутствие очереди. Период смены семени выбирается случайно в рекомендуемом интервале 105–120 минут.

```text
# добавить в torrc узла 009h после настроек HiddenService
HiddenServicePoWDefensesEnabled 1
```

Отправьте HUP **только** этому узлу частной сети:

```bash
docker exec torbook-network sh -c 'kill -HUP $(cat /lab/net/nodes/009h/pid)'
```

После применения новой настройки сервис должен опубликовать обновлённый дескриптор. При его получении через [лабораторную работу 8](Лабораторная-08-Onion.md) во внутреннем слое можно наблюдать строку `pow-params`:

```text
pow-params v1 9qe8kJUi30tgcAlInd5a+trFeVl1yjQtPRb0F4u9C7Y= 0 2026-09-24T17:56:10
```

Она содержит версию схемы `v1`, семя в base64, рекомендованное усилие и время окончания действия семени. В историческом примере рекомендованное усилие равнялось нулю; по этому значению нельзя доказать, что очередь была пуста.

После отправки `HUP` требуется время для публикации и распространения нового дескриптора в частной сети.

## Часть 3 — Работа растёт линейно

**Это только статистическая модель порога Blake2b, не реализация Equi-X.** Случайные 16 байт `solution` не являются корректным доказательством Equi-X. Реальный v1 PoW обязан пройти как проверку Equi-X, так и проверку Blake2b; здесь измеряется только вероятность последней. Для равномерного 32-битного `R` вероятность принятия положительного усилия приблизительно равна `1/effort`.

В стандартной библиотеке Python нет Equi-X. Поэтому лаборатория моделирует только порог приёма Blake2b и показывает вероятность его прохождения на случайных байтах вместо корректных решений Equi-X.

```bash
python3 - <<'EOF'
import os, statistics
from torlab.pow import required_attempts
id_service, seed = os.urandom(32), os.urandom(32)
for effort in (1, 10, 100, 1000):
    trials = [required_attempts(effort, id_service, seed) for _ in range(400)]
    print(f"усилие {effort:>4}: {statistics.mean(trials):.1f} попыток")
EOF
```

```text
усилие    1: 1.0 попыток
усилие   10: 10.5 попыток
усилие  100: 90.0 попыток
усилие 1000: 1027.7 попыток
```

Числа меняются между запусками из-за случайного выбора кандидатов; математическое ожидание количества попыток приблизительно пропорционально заданному усилию.

Важная деталь: Blake2b с `digest_size=4` **не равен** первым четырём байтам обычного 64-байтового хеша. Длина результата входит в параметры Blake2b и меняет само вычисление.

## Известные проблемы

| Симптом | Причина |
|---|---|
| Сразу отклоняются все 30 цепей | IP-адрес мог остаться помеченным после предыдущего опыта. Дождитесь окончания периода защиты или используйте другой исключительно локальный тестовый адрес. |
| При двух каналах нет отказов | Возможно, ретранслятор не применил новую конфигурацию. Проверьте журнал `notice.log` узла `003r`. |
| В дескрипторе нет `pow-params` | Проверьте, включён ли модуль `pow`, GPL-сборка и успел ли сервис опубликовать новый дескриптор. |
