## Что демонстрирует эта работа

В лабораторной работе рассматриваются документы каталога и некоторые проверки их целостности в частной сети. Удостоверяющие узлы подписывают консенсус, а SHA-256 микродескриптора связывает его с записью `m`. Учебный код показывает эти операции, **но не завершает аутентификацию всей цепочки доверия**.

Не менее важно доказать, что проверка **падает тогда, когда должна**: изменение значения пропускной способности в подписанной части консенсуса делает соответствующие RSA-подписи недействительными.

## Запуск эксперимента

```bash
python3 - <<'EOF'
import base64
from torlab.circuit import build
from torlab.laboratory import relay
from torlab.directory import *

# одноузловая цепь к лабораторной службе каталога без управления перегрузкой
circ = build([relay("000a")], cc=False)
text = download(circ, "/tor/status-vote/current/consensus-microdesc", 1).decode()
c = parse_consensus(text)
print(f"консенсус: {len(text)} байт; {' '.join(c.header['valid-after'])}"
      f" -> {' '.join(c.header['fresh-until'])}")

cert = parse_certificates(download(circ, "/tor/keys/all", 3).decode())
print(f"метод {c.header['consensus-method'][0]}; подписей {len(c.signatures)}; сертификатов {len(cert)}")
for r in c.relay[:2]:
    print(f"  {r.name} {r.ip}:{r.orport} w={r.bandwidth} flag={sorted(r.flag)[:4]}...")

valid, required, _ = verify_consensus(c, cert, 3)
assert valid >= required, "not enough signatures matching the provided test certificates"
print(f"совпавших подписей: {valid} (требуется: {required})")

# отрицательная проверка: изменяем найденное значение Bandwidth в текущем консенсусе
import re
bandwidth = re.search(r"Bandwidth=(\d+)", text)
assert bandwidth is not None, "missing Bandwidth field"
altered_text = text.replace(bandwidth.group(0), f"Bandwidth={int(bandwidth.group(1)) + 1}", 1)
assert altered_text != text
modified = parse_consensus(altered_text)
negative_valid = verify_consensus(modified, cert, 3)[0]
assert negative_valid == 0, "modified document passed signature check"
print("изменённый консенсус -> совпавших подписей:", negative_valid)

dig = "-".join(base64.b64encode(r.microdesc).decode().rstrip("=") for r in c.relay)
md = parse_microdescriptors(download(circ, f"/tor/micro/d/{dig}", 5).decode())
assert all(r.microdesc in md for r in c.relay), "missing requested microdescriptor"
print(f"микродескрипторов: {len(md)}; совпадают с записями m: "
      f"{all(r.microdesc in md for r in c.relay)}")
EOF
```

## Ожидаемый вывод

`valid-after` и `fresh-until` описывают интервал *актуальности* консенсуса, тогда как `valid-until` — отдельную границу допустимости. Значения из частной сети являются примером, а не всеобщим сроком действия.

**Граница безопасности:** учебный проверяющий сопоставляет RSA-подписи консенсуса с сертификатами, загруженными с того же сервиса каталогов. Он **не** проверяет их по заранее доверенным ключам идентичности удостоверяющих узлов, не проверяет сертификатные подписи и перекрёстную сертификацию, сроки действия сертификатов и время актуальности консенсуса. Поэтому большинство совпавших подписей **не доказывает подлинность** авторитетного консенсуса сети Tor.



Ниже приведён исторический пример вывода частной сети; значения не гарантированы.

```text
консенсус: 5961 байт; 2026-09-24 16:01:20 -> 2026-09-24 16:01:40
метод 36; подписей 3; сертификатов 3
  test000a 127.0.0.1:5100 w=20 flag=['Authority', 'Fast', 'Guard', 'HSDir']...
  test005r 127.0.0.1:5105 w=4096 flag=['Fast', 'Guard', 'HSDir', 'Running']...
совпавших подписей: 3 (требуется: 2)
изменённый консенсус -> совпавших подписей: 0
микродескрипторов: 8; совпадают с записями m: True
```

Как читать результат:

- Частная сеть использует короткие периоды голосования. `valid-after` → `fresh-until` означает период актуальности, а `valid-after` → `valid-until` — срок действия. Исторический пример не устанавливает всеобщего периода в 40 секунд.
- **Три совпавшие подписи из трёх сертификатов, при пороге 2** показывают порог строгого большинства для тестовой сети, но не устанавливают доверие к сертификатам.
- **Нуль совпавших подписей** после изменения консенсуса подтверждает, что учебный проверяющий обнаружил манипуляцию. Проверяющий, который всегда возвращает успех, ничего не подтверждает.
- SHA-256 каждого скачанного микродескриптора совпадает с соответствующей записью `m` консенсуса: это подтверждает связь по хешу, **но не полную подлинность сертификатов удостоверяющих узлов**.

## Деталь, которая чаще всего ломает проверку

Signature покрывает не весь файл: signed text заканчивается сразу после буквального ключевого слова `directory-signature `, включая следующий за ним пробел. Файлы, скачанные из **CollecTor**, также могут начинаться с annotation вроде `@type network-status-microdesc-consensus-3 1.0`; эта строка **не является частью подписанного документа**.

Если включить annotation в digest, одновременно провалятся все signatures. Симптом выглядит как криптографическая ошибка, хотя проблема лишь в framing документа. Поэтому `signed_text` начинает обработку с настоящего network-status document; это закреплено regression test.

## Известные проблемы

| Симптом | Причина |
|---|---|
| `RELAY_END NOTDIRECTORY` или HTTP `503` | Первый ответ относится к отсутствующему сервису каталога у ретранслятора, второй — к HTTP. Проверяйте фактический ответ и доступность службы. |
| `valid signatures: 0` при отдельно загруженном архивном консенсусе | Проверьте строку `@type`, соответствие исторических сертификатов и границы подписанного документа; архивные файлы требуется загрузить отдельно. |
| HTTP `503` от службы каталога | Проверьте HTTP-ответ и выберите работающий узел каталога; ретранслятор без каталога может вместо этого отправить `END NOTDIRECTORY`. |
| В consensus меньше relay, чем ожидалось | Документ мог быть получен во время перехода между consensus в приватной сети. Повторите примерно через полминуты. |

# Подробности реализации

`labs/ru/код/torlab/directory.py` содержит около 230 строк и решает четыре задачи: загружает directory documents через circuit, parses их, проверяет signatures и привязывает microdescriptors обратно к consensus.

## Загрузка через цепь

```python
def download(circ: Circuit, path: str, stream_id: int) -> bytes:
    """HTTP/1.0 GET к directory service финального hop через BEGIN_DIR."""
    s = Stream(circ, stream_id)
    circ.send(RelayMessage(RelayCommand.BEGIN_DIR, stream_id, b""))
    _, msg = s._next()
    if msg.command != RelayCommand.CONNECTED:
        raise CircuitError(f"BEGIN_DIR отклонён: {msg.command}")
    s.send(f"GET {path} HTTP/1.0\r\n\r\n".encode())
    response = s.receive_all()
    header, _, body = response.partition(b"\r\n\r\n")
    state = header.split(b"\r\n")[0]
    if b" 200 " not in state:
        raise CircuitError(f"{path}: {state.decode()}")
    return body
```

`BEGIN_DIR` обращается к службе каталога последнего ретранслятора, а не к внешнему TCP-серверу. Клиент ОБЯЗАН посылать пустое тело, ретранслятор ОБЯЗАН игнорировать полученное тело. При успехе сервер ОБЯЗАН отправить `CONNECTED` с пустым телом, а клиент — игнорировать его содержимое. Узел без каталога может вернуть `RELAY_END NOTDIRECTORY`, не HTTP `503`.

Цепь из одного перехода здесь представляет **неанонимный** пример запроса общедоступного каталога. Tor допускает такое построение, но не требует его для каждой операции с каталогами; дескрипторы onion-сервисов требуют отдельного подхода к анонимности.

```python
circ = build([relay("000a")], cc=False)
```

Запрос выполняется через **одноузловую цепь**, без согласования управления перегрузкой. Это допустимый способ неанонимного доступа к публичному каталогу, но не обязательная схема для каждой операции Tor.

> Это упрощение относится к публичным directory documents вроде consensus, **но не** к onion-service descriptors. Для них anonymity requester важна, и HSDir отклоняют неподходящий one-hop access; см. [лабораторную работу 8](Лабораторная-08-Onion.md).

## Формат netdoc

Метод `items` — учебный разбор ожидаемого netdoc, а не полноценный защищённый валидатор. Например, усечённый объект PEM может привести к исключению.

```python
def items(text: str) -> list[Item]:
    """Разделить документ формата netdoc на items (dir-spec, netdoc)."""
    output, lines, i = [], text.split("\n"), 0
    while i < len(lines):
        line = lines[i]
        i += 1
        if not line:
            continue
        keyword, *arguments = line.split(" ")
        object_text = None
        if i < len(lines) and lines[i].startswith("-----BEGIN "):
            j = i
            while not lines[j].startswith("-----END "):
                j += 1
            object_text = "\n".join(lines[i:j + 1]).encode()
            i = j + 1
        output.append(Item(keyword, arguments, object_text))
    return output
```

Документы каталогов Tor — консенсусы, голоса, дескрипторы ретрансляторов, микродескрипторы и сертификаты удостоверяющих узлов — используют общий метаформат: ключевое слово, аргументы, разделённые пробелами, и необязательный PEM-подобный объект в следующих строках. Поэтому небольшой разборщик `items` можно переиспользовать в специализированных анализаторах.

`parse_consensus` работает как state machine: строка `r` начинает relay entry, а `s`, `w`, `p` и `m` заполняют её свойства. `r` содержит nickname, identity, адрес и порт; `w` — bandwidth; `m` — digest microdescriptor.

## Граница подписи и критический байт

Реальная функция начинает с `network-status-version `, отбрасывая строку CollecTor `@type`, и заканчивает после первого `directory-signature `. Совпадение RSA-подписи **не подтверждает** происхождение и сроки действия сертификата удостоверяющего узла.

```python
def signed_text(text: str) -> bytes:
    """Часть consensus, покрываемая signatures: от "network-status-version" до
    space after "directory-signature" (dir-spec, "directory-signature").

    Files downloaded from CollecTor begin with an annotation line, "@type ...",
    which is not part of the signed document and must be discarded.
    """
    start = text.index("network-status-version ")
    pos = text.index("\ndirectory-signature ") + len("\ndirectory-signature ")
    return text[start:pos].encode()
```

Signature **не покрывает весь документ**. Она покрывает текст до буквального `directory-signature` и следующего пробела. Один лишний или отсутствующий байт меняет digest.

Особенно важно это для **CollecTor**, где архивный файл может начинаться так:

```text
@type network-status-microdesc-consensus-3 1.0
network-status-version 3 microdesc
```

Строка `@type` — metadata архива, **не часть подписанного network-status document**. Если её включить, все signatures одновременно станут недействительными. Одновременный провал всех подписей — полезный признак ошибки framing, а не одного authority key.

```python
def verify_signature(consensus: Consensus, signature: Signature, cert: AuthorityCertificate) -> bool:
    """Signature — RSA PKCS#1 v1.5 над digest *без* identifier алгоритма:
    восстановить digest из signature и сравнить с вычисленным digest."""
    h = hashlib.sha256 if signature.algorithm == "sha256" else hashlib.sha1
    expected = h(signed_text(consensus.text)).digest()
    try:
        recovered = cert.signing_key.recover_data_from_signature(
            signature.signature, padding.PKCS1v15(), None)
    except Exception:
        return False
    return recovered == expected
```

`recover_data_from_signature` с algorithm `None` восстанавливает digest из исторического RSA signature format Tor без требования обычной ASN.1 DigestInfo. Обычный high-level `verify()` с ожиданием стандартного encoded algorithm identifier поэтому может отвергать корректные Tor signatures.

Hash algorithm берётся из metadata signature. Современные consensus signatures используют SHA-256, но parser способен обработать и форматы с SHA-1, если такой вариант допускается соответствующим network format.

Constant-time comparison здесь не нужен, потому что и expected digest, и подписываемый document публичны. В отличие от этого, ntor-v3 `AUTH` в лабораторной работе 3 зависит от секретного состояния и сравнивается через `hmac.compare_digest`.

## Связь хешей и границы доверия

Полная цепочка начинается с **заранее доверенных ключей удостоверяющих узлов**, проверки сертификатов подписания и срока действия консенсуса. Лишь затем SHA-256 в строке `m` связывает микродескриптор и его `ntor-onion-key` с доверенным документом. Учебный код проверяет совпадение подписей и хешей, но не весь корень доверия; для безопасного подключения к публичной сети он не подходит.

```text
доверенные ключи авторитетов → проверенные сертификаты → подписанный консенсус → SHA-256 `m` → микродескриптор → `ntor-onion-key`
```

## Отрицательная проверка

Явные проверки подтверждают, что подписанный текст действительно изменён и упрощённый RSA-проверяющий распознал подмену. Это не тест привязки к доверенным ключам.

```python
import re
bandwidth = re.search(r"Bandwidth=(\d+)", text)
assert bandwidth is not None, "missing Bandwidth field"
altered_text = text.replace(bandwidth.group(0), f"Bandwidth={int(bandwidth.group(1)) + 1}", 1)
assert altered_text != text
altered = parse_consensus(altered_text)
assert verify_consensus(altered, cert, 3)[0] == 0
```

Verifier, который никогда не падает, ничего не доказывает. Изменение одного numerical value и падение valid-signature count до нуля отличает настоящую проверку от функции, безусловно возвращающей success.

Тест специально **не** hard-code значение вроде `Bandwidth=4096`: measured bandwidth в приватной сети меняется. Если искомой строки нет, `replace` ничего бы не изменил и negative test мог бы бессмысленно «пройти». Поэтому и пример, и `lab6` сначала находят реально присутствующий `Bandwidth`.

## Что важно знать для успешного запуска

- **Не каждый ретранслятор хранит каталог.** Узел без него может вернуть `END NOTDIRECTORY`, а HTTP-сервис каталога — ошибку `503`. Используйте рабочий авторитетный узел частной сети: `000a`, `001a` или `002a`.
- Consensus приватной сети намеренно короткоживущий. Загрузка во время перехода между votes может давать промежуточные наблюдения; повторите после следующего vote.
- Microdescriptor consensus и full consensus — **разные flavors** с различными relay-line formats, хотя принципы проверки signatures одинаковы.
- Endpoint microdescriptor имеет вид `/tor/micro/d/<digests separated by ->` и использует base64 digests без завершающего `=`.
