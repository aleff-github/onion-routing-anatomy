> **Используйте только искусственно созданный собственный трафик в частной сети.** Эксперимент не предполагает наблюдения за коммуникациями других людей.

## Что на самом деле измеряет эксперимент

Скрипт создаёт **шесть одновременных синтетических TCP-потоков через один процесс Tor-клиента** `008c`, работающий на SOCKS-порту 9008. Он **не запускает шесть независимых экземпляров Tor**. Для каждого потока используются отдельные учётные данные SOCKS, указывающие разные контексты изоляции; это **не гарантирует**, что каждому запросу будет выделена своя постоянная цепочка Tor.

На стороне отправителя фиксируется время после вызова `sendall`; на стороне получателя — время вызовов `recv` на **контролируемом локальном сервере** `127.0.0.1:8095`. Таким образом, **это не пассивный перехват пакетов на выходном ретрансляторе Tor**: в качестве второго наблюдателя выступает сам сервер назначения, а измерения производятся на одной машине.

В начале каждого потока передаются **четыре байта открытого идентификатора**. Получатель записывает его как заранее известное соответствие для оценки результата; **вычисление корреляции Пирсона не использует этот идентификатор**. Однако сервер действительно может прочитать такую метку, поэтому опыт **не доказывает**, что посторонний наблюдатель сможет определить неизвестного пользователя только по временным параметрам.

## Подготовка и запуск

Из корня репозитория соберите образ (только при первом запуске) и запустите частную сеть одного языкового издания:

```bash
# Перед первым запуском: make -C labs/ru/лаборатория image
make -C labs/ru/лаборатория start
docker exec -w /tmp torbook-network python3 /lab/correlation.py 3
```

Аргумент `3` — **начальное значение генератора псевдослучайных чисел**. Оно воспроизводит случайные решения, **но не точные моменты отправки, порядок потоков или коэффициенты корреляции**: на них влияют планировщик потоков ОС, буферизация TCP и задержки цепочек. Измеряются байты в интервалах по **250 мс**, номинально в течение **20 секунд**. Установка соединений и очистка занимают дополнительное время.

## Исторический пример результата (не гарантируется)

```text
клиент 0: +0.24 -0.04 +0.09 +0.86 +0.00 -0.04  -> поток выхода 3 ВЕРНО
клиент 2: -0.03 +0.85 +0.35 -0.07 +0.13 -0.05  -> поток выхода 1 ВЕРНО
клиент 5: +0.87 -0.01 +0.27 +0.26 +0.05 +0.15  -> поток выхода 0 ВЕРНО
клиент 4: +0.09 +0.32 +0.85 -0.07 +0.02 +0.10  -> поток выхода 2 ВЕРНО
клиент 1: +0.24 -0.07 +0.19 +0.08 -0.03 +0.72  -> поток выхода 5 ВЕРНО
клиент 3: +0.17 +0.13 +0.04 +0.13 +0.70 +0.09  -> поток выхода 4 ВЕРНО
правильных совпадений: 6/6
```

В каждой строке перечислены шесть **коэффициентов корреляции Пирсона** между временным рядом исходящего потока и рядами, полученными на стороне сервера. При этом учитывается **число байтов за интервал**, а не время отдельных перехваченных сетевых пакетов. Сервер присваивает номера потокам по порядку прихода соединений; номера и значения могут меняться между запусками.

Для каждого отправителя отдельно выбирается **максимальный коэффициент**. Скрипт **не строит глобального взаимно однозначного соответствия**: два отправителя могут выбрать одну и ту же запись на стороне получателя. Известная правильная метка применяется **только после выбора** для вывода `ВЕРНО` или `ОШИБКА`. Если ряд постоянен или неполон, достоверный коэффициент получить нельзя.

В старой записи получилось 6/6, но в учебном критерии допустимо и 5/6. В скрипте проверяется наличие всех шести потоков, корректно обрабатываются частичные ответы SOCKS5 и ошибки рабочих потоков, отбрасываются некорректные ряды. Если правильных соответствий меньше пяти, программа завершает работу с ошибкой. **Это статические исправления: повторный эксперимент не проводился.**

## Чего этот эксперимент не доказывает

Он не измеряет вероятность успеха атаки в публичной сети Tor и не показывает, что любой наблюдатель способен раскрыть личность пользователя. Нужны наблюдения с обеих сторон, сопоставимые часы, достаточно длительная запись, оценка ошибок и учёт фонового трафика. Постоянные входные ретрансляторы ([лабораторная работа 19](Лабораторная-19-Моделирование.md)) сокращают количество новых точек входа, которым клиент раскрывается со временем, но не устраняют корреляцию при уже доступных наблюдениях.

## Автоматическая проверка и возможные ошибки

**Итальянский** проверяющий файл `scripts/verify_labs.py::lab16` принимает последнюю строку с `5/6` или `6/6`, **но не проверяет код завершения подпроцесса**. Это остаётся ограничением проверки. Запусков Docker, Tor, Chutney и сборки книги после правок не было.

| Признак | Что проверить |
|---|---|
| Меньше пяти совпадений | Случайные ритмы могли оказаться похожими; повторите опыт в своей частной сети, сохранив параметры. |
| Ошибка SOCKS5 или отсутствующий поток | Проверить `008c`, порт 9008, этапы согласования SOCKS5 и локальный сервер. |
| Нет пригодных временных рядов | Исправленный код отклоняет постоянные и отсутствующие ряды вместо произвольного ответа. |
| `Address already in use` | Порт 8095 занят предыдущим тестовым сервером; остановите только свой экземпляр. |
