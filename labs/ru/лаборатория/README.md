# Приватная сеть Tor для лабораторных работ

Активные эксперименты русского издания **предназначены только для контролируемой приватной сети Chutney**, а не для публичных ретрансляторов Tor или сторонних сервисов. Подробности приведены в главе 19; здесь дана краткая справка. **Docker запускается с `--network host` и использует сетевое пространство имён хоста: сетевой изоляции контейнера нет.** Используйте лабораторию только на контролируемом тестовом компьютере.

## Содержимое

| Файл или каталог | Назначение |
| --- | --- |
| `Dockerfile` | Сборка Tor 0.4.9.13 из исходников с `--enable-gpl` (для механизма доказательства работы onion-сервисов); Chutney, obfs4proxy, snowflake-client, Stem, tshark и curl |
| `Makefile` | Цели `image`, `start`, `verify`, `status`, `shell`, `stop`, `clean` |
| `chutney/networks/book` | Основная сеть для большинства лабораторных работ |
| `chutney/networks/book-bridge` | Центр каталогов мостов, мост obfs4 и его клиент для лабораторной работы 10; без onion-сервиса |
| `net/` | Создаваемые конфигурации, закрытые ключи, журналы и состояние узлов; не отслеживается Git |
| `*.py` | Примеры для лабораторных работ 11, 13, 14, 16, 17, 18 и 20 |

## Команды

В каталоге `labs/ru/лаборатория/` (из корня репозитория также можно вызвать `make -C labs/ru/лаборатория <цель>`):

```bash
make image     # Собрать образ лаборатории перед первым запуском
make start     # Запустить основную топологию Chutney и выполнить bootstrap
make verify    # Проверить сеть через Chutney, НЕ все лабораторные задания
make status    # Показать состояние узлов Chutney
make shell     # Открыть оболочку контейнера
make stop      # Остановить узлы и удалить контейнер, сохранив net/
make clean     # Остановить сеть и УДАЛИТЬ net/ вместе с ключами и идентичностями
```

Для лабораторной работы 10 используйте `make start NETWORK=book-bridge` **только после остановки предыдущей сети и проверки/удаления её временного состояния**. Топология с мостом содержит **12 узлов**, а не 10, и не включает onion-сервис. Цель `make riavvia` в корне репозитория относится **только к итальянскому** контейнеру и не перезапускает русскую среду.

Makefile сред EN, RU и ZH-CN используют одинаковые имена образа и контейнера (`torbook-lab:latest`, `torbook-network`) и пересекающиеся порты хоста. **Не запускайте сети этих редакций одновременно.** Настоящая ревизия исходных текстов не подтверждает выполнение сборок, запуск Chutney или экспериментов.

## Основная топология `book`

Десять узлов с локальными адресами `127.0.0.1`:

| Узлы | Роль | ORPort | ControlPort | Другое |
| --- | --- | --- | --- | --- |
| `000a`–`002a` | Центры каталогов и ретрансляторы | 5100–5102 | 8000–8002 | DirPort 7100–7102 |
| `003r`–`005r` | Промежуточные ретрансляторы | 5103–5105 | 8003–8005 | — |
| `006e`, `007e` | Выходные ретрансляторы для частных локальных адресов | 5106, 5107 | 8006, 8007 | Диапазон назначения `127.0.0.0/8` |
| `008c` | Клиент | — | 8008 | SocksPort 9008 |
| `009h` | Onion-сервис | — | 8009 | Виртуальный порт 5858 → `127.0.0.1:4747` |

Для соответствующих ролей Chutney использует правило ORPort `5100+n` **только для ретрансляторов**, ControlPort `8000+n`, SocksPort `9000+n` **для клиентов**. Клиенту или onion-сервису не назначается ORPort ретранслятора только по номеру узла. В итальянском оригинале указан интервал голосования центров каталогов в 20 секунд, но **реальное время голосования и получения консенсуса требует проверки при запуске**.

## Устранение неполадок

- **`address already in use`**: порт хоста может занимать другая программа или сеть иной редакции, включая HTTP-серверы на 4747 или 8080. Остановите конфликтующий процесс. `--network host` не предотвращает конфликты портов.
- **Узлы работают, но не отвечают**: после аварийной остановки могут оставаться устаревшие файлы `pid`. Проверьте состояние Chutney перед перезапуском; корневая итальянская цель `riavvia` для RU не подходит.
- **С первого раза не построилась цепь**: в небольшой сети возможны временные сбои. Повторяемый отказ требует диагностики, а повторный запуск сам по себе не доказывает успех.
- **Не запускается клиент**: Chutney может требовать второй этап запуска (`CHUTNEY_LAUNCH_PHASE=2`). Проверьте журналы и топологию; не считайте успешным один лишь вызов `make start`.
- **Команда `make start` прервалась**: Makefile не откатывает частично созданные контейнер и сеть. Перед повторной попыткой проверьте состояние и логи. `make clean` безвозвратно удаляет сгенерированные идентичности узлов.

## Предупреждение

Некоторые сценарии намеренно создают необычный трафик, некорректные ячейки Tor и контролируемые пробы. **Запускайте их только в приватной временной сети Chutney.** Нельзя испытывать их на публичных ретрансляторах или действующих сервисах: это может навредить другим пользователям и нарушить закон (глава 25). Каталог `net/` содержит закрытые ключи лаборатории: **не публикуйте его**. Результаты, приведённые в книге, получены в эталонных запусках; ваш запуск может отличаться в деталях.
