| 项目 | 内容 |

## 实验目标

v3 洋葱服务可以要求客户端提供 **X25519 授权密钥**，才能解密服务描述符的受保护内层。没有正确私钥的客户端无法从该层获取引介点信息，通常也无法建立连接。描述符本身仍可从 HSDir 下载：**取得描述符并不等于能够解密它**。受限发现机制在应用程序登录之前生效。

**重要安全条件：**Tor 只有在成功加载至少一个有效 `.auth` 文件后才会启用客户端授权。**空的** `authorized_clients` 目录**不能视为保护措施**：没有启用授权时，知道洋葱地址的人可能都能访问服务。旧实验中的 `400 Invalid HS descriptor` 只是特定版本的观察结果，**不是所有 Tor 版本均会拒绝的保证**。

## 准备

从仓库根目录操作，且仅在可丢弃的私有实验网络中执行。不同语言版本共享宿主机端口，不要同时启动。首次使用应先构建镜像，再启动只绑定本地回环地址的 HTTP 服务器：

```bash
# 首次执行前：make -C labs/zh-Hans/实验室 image
make -C labs/zh-Hans/实验室 start
python3 -m http.server 8080 --bind 127.0.0.1 &
export PYTHONPATH=labs/zh-Hans/代码
```

脚本在 `009h/restricted_service` 下创建**第二个**临时洋葱服务，不修改原有服务。写入前会检查 `restricted_service`、`onion_auth` 和 `torrc` 中是否已有相关授权设置；如果发现旧状态，脚本会**拒绝执行且不自动删除**。新密钥文件采用限制性权限。若恢复配置后的 Tor 重载失败，临时密钥会保留供人工检查。

## 参考输出（因运行而异）

```text
受限服务：4stlyhm3pkptxitznaip66qf3tnuhujabwq6louhibhds7lwk7qcoeyd.onion
无授权密钥：000
有授权密钥：200
```

重新创建服务后，地址、等待时间和 HTTP 结果都可能不同。**`000` 只表示 curl 未收到 HTTP 状态码，不足以证明服务器因缺少授权密钥而拒绝访问。**本地 HTTP 服务未启动、SOCKS 失败、超时或私有网络尚未就绪，都可能产生该值。**`200`** 表明持有密钥的请求到达了测试服务器，但不能单凭它判断先前失败的原因。

## 工作原理

1. 生成新的 **X25519 密钥对**，在节点 `009h` 创建第二个临时服务。
2. 重载服务前，将**公钥**写入 `<HiddenServiceDir>/authorized_clients/alice.auth`，格式为 `descriptor:x25519:<base32公钥>`。必须有至少一个有效、可读的 `.auth` 文件被 Tor 成功加载。
3. 在客户端 `008c` 设置 `ClientOnionAuthDir`。进行授权测试时，将**私钥**保存为 `alice.auth_private`，格式为 `<不含.onion后缀的地址>:descriptor:x25519:<base32私钥>`。
4. 先验证节点 PID 及其命令行，只向对应的 Tor 进程发送 HUP。通过本地 SOCKS 代理先请求无密钥的服务，再安装私钥重试；明确禁用 `NO_PROXY` 绕过。
5. `finally` 块会恢复两个原始 `torrc`，尝试重载 Tor，然后才删除**本次执行创建的**临时目录。如果进程被 `SIGKILL` 强制结束，`finally` 不会执行；应人工核实实验状态。

当前脚本在输出不符合无密钥 `000`、有密钥 `200` 时会报错。这只是**教学检查**，并非完整的描述符安全性或密码学验证。

## 已知问题与恢复

| 现象 | 检查项目 |
|---|---|
| 两次请求都得到 `000` | 检查 8080 端口的本地 HTTP 服务、网络引导、描述符发布、SOCKS 配置以及 Tor 日志。 |
| `ClientOnionAuthDir` 导致客户端退出 | 该指令必须使用由节点 `DataDirectory` 推导出的**容器内路径**，而不是宿主机路径。 |
| 运行前已经存在授权目录 | 脚本会拒绝继续。仅检查临时私有网络的 `torrc`、`restricted_service` 和 `onion_auth`；不要盲目删除密钥。 |
| 出现 `400 Invalid HS descriptor` 或无密钥访问意外成功 | 确认 Tor 确实加载了至少一个有效 `.auth`；空目录并不证明保护已启用。 |
| HUP 或配置恢复失败 | 检查目标进程 PID、`torrc` 和保留的临时密钥；不要在真实服务上使用广泛匹配的 `pkill -HUP -f` 或破坏性清理。 |
