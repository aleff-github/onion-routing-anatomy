## 实验目标

手动为应用设置 Tor 时，常见错误是让**应用程序先在本地解析域名**，而不是把域名交给 tor。即使后续 TCP 连接仍通过 Tor，域名也可能已经在 Tor 电路之外暴露；是否有外部 DNS 查询以及是否为明文，取决于缓存及解析配置。

本实验还展示 tor 在配置适当时，如何**发现这种风险信号**。

## 准备

从仓库根目录操作。首次运行先执行 `make -C labs/zh-Hans/实验室 image` 构建镜像。各语言实验网络共享宿主机端口，不要同时启动。

```bash
make -C labs/zh-Hans/实验室 start
```

脚本会自行启动仅返回固定文字的本地 HTTP 测试服务器，不公开目录中的文件，并使用 Stem 读取客户端 ControlPort 的警告，因此应**在容器内部运行**；该环境将宿主机的 `labs/zh-Hans/实验室/` 挂载为 `/lab/`：

```bash
docker exec -w /lab torbook-network python3 /lab/dns_leak.py
```

## 历史输出示意（不保证一致）

程序会打印**三行**，每次测试一行。Tor 通知会截断到 110 个字符，并可能因版本变化。以下只是**示意性片段**，不是保证逐字相同的输出：

```text
--socks5           HTTP 200  tor: ... only an IP address ...
--socks5-hostname  HTTP 200  tor: ... DNS resolution itself if necessary ...
--socks5 SafeSocks HTTP 000
```

其中的英文是 tor 本身产生的诊断文本，保留以便读者与实际日志进行逐字对照。

- **`--socks5`：**curl 在本地解析域名，仅把 **IP 地址**交给 tor。示例中的 HTTP 请求仍能成功，因此这种有风险的请求形式容易被忽略，但这并不证明 DNS 已经泄露。脚本暂时启用 `TestSocks 1`，让 tor 报告这种可能不安全的请求形式。
- **`--socks5-hostname`：**通过 SOCKS 将**主机名**传给 tor，让出口侧完成必要的解析。这是推荐形式。
- **`SafeSocks 1`：**tor 不再只是警告，而是直接拒绝只包含 IP 的请求；curl 因没有建立 HTTP 连接而报告 `000`。

因此，仅仅更换命令行选项中的几个字符，就可能改变域名在哪里被解析。这也是普通用户应优先选择 Tor Browser、而不是自行配置各种应用代理的原因之一。

> **重要限制：**实验使用 `localhost`，它会直接解析到环回地址，不会向外部 DNS 服务器发出查询。因此，**本实验并未产生真正的 DNS 泄露**。它只证明：使用 `--socks5` 时应用先解析域名，tor 最后只收到 IP。把 `localhost` 换成普通域名可能产生外部 DNS 查询；是否为明文取决于解析配置，而私有网络实验刻意避免这种情况。

## 三个相关 tor 选项

| 选项 | 效果 |
|---|---|
| `TestSocks 1` | 记录 tor 收到的 SOCKS 请求形式，仅供诊断 |
| `SafeSocks 1` | 拒绝只提供 IP 地址的请求 |
| `WarnUnsafeSocks` | 输出警告；参考版本默认启用 |

这些选项**无法阻止应用联系 tor 之前已经发生的 DNS 查询**，只能根据收到的 SOCKS 请求形式作出反应。脚本使用 `--noproxy ''`，以避免 `NO_PROXY` 让 `localhost` 绕过代理。

**安全与配置恢复：**程序仅在 `127.0.0.1:8080` 返回固定文本，**不会公开工作目录中的文件**；如果端口被占用，则立即停止。使用 `--noproxy ''` 防止绕过 SOCKS。先保存 `TestSocks` 和 `SafeSocks` 的原值，再于 `finally` 中尝试恢复，即使 curl 报错也会恢复；强制终止仍可能阻止恢复。程序同时检查 HTTP 状态、curl 的退出状态以及 Tor 对应的诊断通知，否则以错误状态结束。`localhost` 通常由本地名称服务解析，但**本脚本没有捕获 DNS 数据包**，不能证明绝对没有 DNS 查询。

## 已知问题

| 现象 | 原因 |
|---|---|
| 没有警告 | 脚本可能未能通过 ControlPort 的 `SETCONF` 启用 `TestSocks` |
| 第三个测试仍返回 `200` | `SafeSocks` 没有正确生效 |
| 三项测试全部返回 `HTTP 000` | 私有网络或脚本启动的本地测试服务器可能未工作 |
