## 实验目的

在**拥有自己的 TLS 会话密钥**的前提下，从外部查看 Tor 连接的内部结构。我们使用 `tcpdump` 捕获自己生成的流量，让自己的客户端通过 `SSLKEYLOGFILE` 导出 TLS 密钥，再用 `tshark` 解密抓包。这样可以按握手顺序逐条看到 Tor cell。

这是恰当的实验方式：**只解密自己的通信**，使用程序主动导出的密钥，不拦截或攻击第三方流量。

## 运行实验

下例在宿主机执行 Python，通过 Docker 在容器内抓包和解码：

```bash
python3 - <<'PY'
import os, subprocess, time
from torlab.cells import CellCommand as C
from torlab.circuit import build
from torlab.laboratory import relay, NODES
from torlab.traffic import cells_from_follow as parse

network = "torbook-network"
keys = NODES.parent / "keys.log"
capture = NODES.parent / "capture.pcap"
# 此处使用临时实验文件：旧版本将被覆盖。
keys.unlink(missing_ok=True)
capture.unlink(missing_ok=True)

# 1. 仅抓取本地中继端口 5104 的流量
subprocess.run(["docker", "exec", "-u", "0", "-d", network, "sh", "-c",
                "timeout 12 tcpdump -i lo -w /lab/net/capture.pcap 'tcp port 5104'"],
               check=True)
time.sleep(2)

# 2. 建立私有通道并导出 TLS 密钥
previous = os.environ.get("SSLKEYLOGFILE")
os.environ["SSLKEYLOGFILE"] = str(keys)
try:
    circuit = build([relay("004r")], cc=False)
    circuit.channel.sock.close()
finally:
    if previous is None:
        os.environ.pop("SSLKEYLOGFILE", None)
    else:
        os.environ["SSLKEYLOGFILE"] = previous
# 等待限时抓包结束后，再让 tshark 打开文件。
time.sleep(12)
if not keys.exists() or not keys.stat().st_size:
    raise RuntimeError("未导出 TLS 会话密钥")
keys.chmod(0o600)
print("TLS 密钥日志行数:", len(keys.read_text().splitlines()))

# 3. 检索 TLS TCP 流并重建 Tor cell
opts = ["-r", "/lab/net/capture.pcap", "-d", "tcp.port==5104,tls",
        "-o", "tls.keylog_file:/lab/net/keys.log"]
scan = subprocess.run(["docker", "exec", network, "tshark", *opts,
                       "-Y", "tls && tcp.port==5104", "-T", "fields", "-e", "tcp.stream"],
                      check=True, capture_output=True, text=True)
stream_ids = sorted({int(v) for v in scan.stdout.split() if v.isdigit()})
found = False
for stream_id in stream_ids:
    result = subprocess.run(["docker", "exec", network, "tshark", *opts,
                             "-q", "-z", f"follow,tls,raw,{stream_id}"],
                            check=True, capture_output=True, text=True)
    try:
        cells = parse(result.stdout)
        names = [(direction, C(cell.command).name)
                 for direction, cell, _ in cells]
    except (ValueError, IndexError):
        continue
    if len(names) >= 2 and [name for _, name in names[:2]] == ["VERSIONS", "VERSIONS"] \
            and "CREATED2" in [name for _, name in names]:
        print(f"流 {stream_id}:")
        for direction, cell, version in cells:
            print(f"  {direction} {C(cell.command).name} (消息体 {len(cell.body)} byte)")
        found = True
        break
if not found:
    raise RuntimeError("未找到完整 VERSIONS / CREATED2 序列，请检查抓包和密钥日志")
PY
```

## 参考输出

```text
TLS keys exported: 6 lines
flow 1:
   client VERSIONS (body 4 byte)
   relay VERSIONS (body 6 byte)
   relay CERTS (body 1446 byte)
   relay AUTH_CHALLENGE (body 36 byte)
   relay NETINFO (body 509 byte)
   client NETINFO (body 509 byte)
   client CREATE2 (body 509 byte)
   relay CREATED2 (body 509 byte)
```

输出中的英文是脚本原始标签，方便与实际终端结果比较。

- 这就是[实验 1](实验-01-通道.md)中的通道握手，只不过这次是从抓包侧观察：从 TLS 承载的字节重建相同顺序的 cell。
- 环回接口还可能承载其他连接，因此无法预先知道 TLS 流编号。示例会查找端口 5104 上被 `tshark` 识别为 TLS 的**所有 TCP 流索引**，并寻找以两条 `VERSIONS` 开始、包含 `CREATED2` 的完整序列；找不到时会明确报错，而非只检查前八个索引。
- `NETINFO`、`CREATE2` 和 `CREATED2` 属于**定长 cell**，其填充后的消息体为 **509 字节**。使用 v4/v5 链路协议时，整个定长 cell 为 **514 字节**（4 字节 CircID、1 字节命令、509 字节消息体）；而 `VERSIONS`、`CERTS` 是变长 cell。没有会话密钥的观察者无法从加密载荷读取这些命令。
- 历史示例中的**六行**不是固定值：密钥日志的行数随 TLS 版本、实现和会话变化，也可能包含注释行。本项目由 Python 客户端的 `ssl.SSLContext.keylog_filename` 写入该日志。

## 不拥有密钥时还能看到什么？

这是第 20 章的核心问题。被动观察者能看到本次私有实验中继的地址、端口、TLS 连接（历史抓包使用 TLS 1.3），以及数据包大小与时间信息；本实验不涉及公开 Tor 共识中的中继。没有会话密钥时，观察者看不到 cell 命令、CircID，也无法直接知道通道上共享了多少条逻辑电路。

但大小与时间仍然重要：它们是端到端流量关联的原始材料。[实验 16](实验-16-流量关联.md)从防御研究角度讨论这一问题。

## 自动验证

意大利语参考验证器 `scripts/verify_labs.py` 的 `lab12` 检查解密后的 cell 序列是否以两条 `VERSIONS` 开始并包含 `CREATED2`；但旧实现只扫描前八个流索引，也不会可靠地传播所有命令失败状态。此处更新的示例改为遍历检测到的 TLS 流并在找不到完整序列时出错。`make -C labs/zh-Hans/实验室 verify` 仅调用 Chutney。

## 常见问题

| 现象 | 原因 |
|---|---|
| 所有 TLS 流都没有 cell | 密钥文件为空；必须在创建 TLS 套接字**之前**设置 `SSLKEYLOGFILE` |
| `tshark` 无法打开 pcap | 容器内抓包需要 root 权限，命令使用了 `docker exec -u 0` |
| 抓包文件为空 | `tcpdump` 在流量发送后才启动；先抓包，稍等片刻再产生连接 |
| 只能解密部分握手 | 抓包在通道仍活跃时就停止；适当延长捕获时间 |
