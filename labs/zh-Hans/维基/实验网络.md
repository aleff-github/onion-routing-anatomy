# 私有实验网络

本书的实验环境在 Docker 容器中使用回环地址 `127.0.0.1` 运行一套完整的 Tor 网络，包括目录权威节点、中继、客户端和洋葱服务。**注意：**Makefile 使用 `--network host`，因此容器**共享宿主机网络**，并不提供独立的网络隔离边界。大多数实验都使用它。第 19 章介绍完整设计。

## 为什么必须自己运行网络？

不要在公共 Tor 网络上尝试本书的主动实验。那里的数据包与真实用户的通信一起经过志愿者中继，许多人依靠 Tor 保护安全。在隔离网络中只是一行代码的操作，放到公共网络中就可能伤害陌生人。

自己的网络允许进行不适合在其他环境开展的实验：故意篡改 MAC 以观察中继反应、超过 `RELAY_EARLY` 配额、触发抗 DoS 防御、解密自己创建的 TLS 会话并逐个检查 cell。

## 网络拓扑

全部十个节点位于 `127.0.0.1`：

| 节点 | 角色 | ORPort | ControlPort | 其他 |
|---|---|---:|---:|---|
| `000a`、`001a`、`002a` | 目录权威兼中继 | 5100–5102 | 8000–8002 | DirPort 7100–7102 |
| `003r`、`004r`、`005r` | 中间中继 | 5103–5105 | 8003–8005 | |
| `006e`、`007e` | 出口中继 | 5106、5107 | 8006、8007 | 连接 `127.0.0.0/8` |
| `008c` | 客户端 | — | 8008 | SocksPort 9008 |
| `009h` | v3 洋葱服务 | — | 8009 | 虚拟端口 5858 → `127.0.0.1:4747` |

**端口规则：**编号为 *n* 的节点使用 ORPort `5100+n`、ControlPort `8000+n`，如果是客户端还使用 SocksPort `9000+n`。全部实验使用一致的规则：`5103` 总是属于 `003r`，`9008` 属于客户端。

Chutney 使用 `test000a`、`test003r` 等名称，本书和 Wiki 有时只写简短名称。

解释实验结果时，需注意它与公共网络的三个不同点：

- 目录权威节点**每 20 秒**投票，而不是每小时一次，因此新共识通常很快出现。
- 只有三台中间中继，所以不同中继、/16 网络和家族等现实路径多样性约束，无法像公共网络一样充分体现。[实验 7](实验-07-路径选择.md) 通过公开共识研究这些问题。
- 全部节点共享一个 IP 地址，因此某些网络防御机制在这个环境中天然受到限制。

另一种拓扑 `book-bridge` **并不是原有十个节点再增加三个节点**：Chutney 定义中有 **12 个节点**，包括三台普通目录权威、一台网桥权威、三台中间中继、两台出口、一台 obfs4 网桥以及两台客户端（其中一台使用网桥）；**不包含洋葱服务节点 `009h`**。它专供[实验 10](实验-10-网桥.md) 使用，执行洋葱服务实验时须恢复普通 `book` 拓扑。

## 常用命令

**运行前提与隔离限制：**请在支持 Docker 与 GNU Make 的 Linux 环境中操作。构建镜像时需要联网取得 Tor、Chutney 和依赖。Docker 的**宿主机网络模式**使各语言环境的端口在同一台主机上共享，**不要同时启动两个语言版本的实验网络**。EN/RU/ZH-CN 还共用镜像名 `torbook-lab:latest` 与容器名 `torbook-network`；ES/IT 虽然命名不同，端口仍然冲突。启动前确认其他实例已经停止。

从仓库根目录执行：

```bash
make -C labs/zh-Hans/实验室 image       # 首次构建实验镜像
make -C labs/zh-Hans/实验室 start       # 创建容器和节点，等待引导
make -C labs/zh-Hans/实验室 verify      # Chutney 端到端测试
make -C labs/zh-Hans/实验室 status      # 查看节点状态
make -C labs/zh-Hans/实验室 shell       # 进入容器
make -C labs/zh-Hans/实验室 stop        # 停止网络并移除容器，保留 net/
make -C labs/zh-Hans/实验室 clean       # 同时删除 net/

PYTHONPATH=labs/zh-Hans/代码 python3 -m pytest -q labs/zh-Hans/代码/torlab/test
```

切换到实验 10 的网桥拓扑：

```bash
make -C labs/zh-Hans/实验室 clean
make -C labs/zh-Hans/实验室 start NETWORK=book-bridge
make -C labs/zh-Hans/实验室 verify
```

完成后先停止并清理网桥拓扑，再重新启动标准 `book`。**注意：**`clean` 会删除整个 `labs/zh-Hans/实验室/net/`，包括临时私钥、洋葱服务身份和运行状态；再次初始化会生成不同的身份。`verify` 只检查当前运行的 Chutney 网络，不等于运行全书所有 Python 测试。中文版不依赖意大利语根目录中的兼容命令。

## 文件位置

```text
labs/zh-Hans/实验室/net/nodes/         十个节点（指向 nodes.<时间戳> 的符号链接）
labs/zh-Hans/实验室/net/nodes/003r/
    torrc                 Chutney 生成的配置
    fingerprint           RSA 身份指纹
    fingerprint-ed25519   在实验中验证的 Ed25519 身份
    notice.log            故障时首先检查的日志
    pid
labs/zh-Hans/实验室/net/nodes/008c/cached-microdescs.new    客户端看到的中继 ntor 密钥
labs/zh-Hans/实验室/net/nodes/009h/hidden_service/hostname  服务的 .onion 地址
```

`labs/zh-Hans/实验室/net/` **不纳入 Git 版本控制**。其中包含私有密钥，即使只是玩具网络，也不应该公开。每次执行 `make -C labs/zh-Hans/实验室 clean && make -C labs/zh-Hans/实验室 start` 都会重新创建这些文件，生成新的节点身份。因此，读者看到的指纹不同于书中记录是正常的。

`torlab.laboratory` 模块可以读取相关信息：

```python
from torlab.laboratory import relay
r = relay("003r")
print(r.port, r.id_ed.hex()[:16], r.ntor.hex()[:16])
```

## 安全规则

实验脚本有意产生非常规流量：格式错误的 cell、超过限制的请求、重复探测和抓包。**只允许在本书私有网络内运行。** 对真实中继或服务执行这些操作会影响用户，也可能违法。第 25 章讨论相关法律问题。

实验 7、15 和 19 分析 Tor Project 通过 CollecTor 发布的**历史公开目录文档**，不向公共 Tor 中继或真实用户发送实验流量。首次获取这些文件需要 **HTTPS 互联网连接**；不能将下载过程描述为完全离线。
