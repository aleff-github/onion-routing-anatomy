## 实验目的

**实验范围：**示例向调用者明确指定的末端中继（`006e`）下载描述符。`download_descriptor()` **不会计算并选择负责的 HSDir**：环索引算法由其他函数实现，并没有通过这次三跳下载得到验证。本例也不具备受限发现的客户端凭据处理能力。

洋葱地址**编码**了 Ed25519 身份公钥、校验和及版本号。仅知道盲化公钥的 HSDir 通常无法直接恢复长期身份；但已经知道 onion 地址的人也能计算相应时间周期的盲化公钥，因此不能把盲化当成对已知地址观察者的匿名保证。

v3 `.onion` 地址**由公钥派生**。客户端从该公钥出发，可以计算当前周期的盲化密钥，确定服务在 HSDir 环上的位置，获取描述符，验证其签名，再逐层解密直至获得引介点。

盲化密钥防止 HSDir 轻易获知它所存储的是哪一个长期服务身份。密钥随时间周期变化，不知道 onion 地址的人，不能直接将其还原为服务的长期身份。

## 运行实验

```bash
python3 - <<'EOF'
import calendar, time
from torlab.circuit import build, CircuitError
from torlab.laboratory import relay, NODES
from torlab.directory import parse_consensus, download
from torlab.onion import *

address = (NODES / "009h/hidden_service/hostname").read_text().strip()
print("address:", address)
A = key_from_address(address)
print("reconstructed from the address:", onion_address(A) == address)

c = parse_consensus(download(build([relay("000a")], cc=False),
                              "/tor/status-vote/current/consensus-microdesc", 1).decode())
ts = lambda k: calendar.timegm(time.strptime(" ".join(c.header[k]), "%Y-%m-%d %H:%M:%S"))
t = time_period_info(ts("valid-after"), ts("fresh-until") - ts("valid-after"), test_network=True)
print("period:", t.period, "duration (min):", t.duration_minutes)
Ap = blinded_key(A, t.period, t.duration_minutes)
print("盲化公钥：", Ap.hex()[:8] + "...")

# 1. 负面测试：只用一跳
try:
    download_descriptor(Ap, [relay("006e")])
    raise AssertionError("单跳描述符请求意外成功")
except CircuitError as e:
    print("单跳电路 ->", e)

# 2. 与真实客户端一样，使用三跳
desc = parse_descriptor(
    download_descriptor(Ap, [relay("003r"), relay("004r"), relay("006e")]), A, Ap)
print(f"lifetime {desc.duration_minutes} revision {desc.revision} "
      f"introduction points {len(desc.introduction_points)}")
for line in desc.inner_layer.splitlines()[:6]:
    print("  ", line[:66])
EOF
```

## 如何定位最初的失败？

最初实现无法从**任何一台**实验 HSDir 下载描述符。逐个检查八台 HSDir 之后，问题不太可能是选错某个 HSDir，更可能出在盲化密钥计算或请求路径上。

研究人员随后通过正式 `tor` 客户端的 ControlPort 获取同一个描述符（先用 `HSFETCH`，再用 `GETINFO hs/client/desc/id/...`）。返回证书揭示了实际使用的盲化密钥，与教学实现计算的完全相同。由此排除了关键算术错误，并确认故障出在请求方式：tor 会拒绝通过一跳电路到达的 v3 洋葱描述符请求。改用正常三跳电路后，下载成功。

更重要的是排障方法：实验失败时，应当找出能够与可信参考实现直接比较的**中间计算结果**。

## 对实验局限的说明

私有网络只有八个 HSDir，而洋葱服务会向 $2\times4=8$ 台发布描述符，实际上就是**所有 HSDir**。因此，成功下载描述符本身**不足以证明**环上位置计算完全正确。

客户端日志会记录实际查询哪台 HSDir，它与教学实现针对对应副本及周期计算的某个位置吻合。这是支持证据，不是完整证明。更强的测试需要更多 HSDir，或者跨多个周期系统地与 tor 比较。

## 自动验证

意大利语历史检查器 `lab8` 依赖正在运行的私有网络；本地化 `test_onion.py` 利用保存的签名测试数据离线测试地址、校验和、描述符、错误周期和公有网络时间周期。两者并非同一项验证。

`lab8` 验证地址重建、一跳请求被拒绝、三跳成功解密且至少获得一个引介点。

## 常见问题

空的 `authorized_clients/` 目录本身不能证明受限发现已启用，也不是 HTTP `400` 的必然原因。仅在实际启用授权时，才需要有效客户端文件及 `auth-client` 条目；应以日志为准。

| 现象 | 原因 |
|---|---|
| `503 Rejecting single hop HS v3 descriptor request` | 这是预期负面测试；真正获取描述符应使用三跳 |
| 所有 HSDir 都返回 `404` | 服务可能尚未发布，或者使用了错误周期派生盲化密钥 |
| 服务日志出现 `400 Invalid HS descriptor` | 检查实际描述符、授权客户端文件和服务日志；不能仅凭 `authorized_clients` 为空就确定原因。参见[实验 13](实验-13-受限发现.md) |

# 实现详解

`labs/zh-Hans/代码/torlab/onion.py` 约 250 行，是仓库中内容最密集的模块之一，结合椭圆曲线运算、时间周期计算、分布式环位置以及两层加密。

## 地址就是公钥

```python
def onion_address(key: bytes) -> str:
    """base32(PUBKEY | CHECKSUM | VERSION) + ".onion" (rend-spec, ONIONADDRESS)."""
    checksum = hashlib.sha3_256(b".onion checksum" + key + bytes([VERSION])).digest()[:2]
    return base64.b32encode(key + checksum + bytes([VERSION])).decode().lower() + ".onion"
```

v3 `.onion` 地址包含 32 字节 Ed25519 公钥、2 字节校验和以及 1 字节版本号，全部使用小写 base32 编码。35 字节在 `.onion` 后缀之前变成 56 个字符。

不存在分配名字的中心注册机构：地址由密钥通过密码学运算派生。校验和不是抵御攻击者的身份认证机制，因为任何人都能重新计算；它主要用于识别输入或抄写错误。前缀 `".onion checksum"` 还提供域分离。

## 盲化因子

```python
def blinding_factor(A: bytes, period: int, duration_minutes: int) -> int:
    n = b"key-blind" + struct.pack(">QQ", period, duration_minutes)
    h = bytearray(hashlib.sha3_256(b"Derive temporary signing key\x00" + A + BASE_STR + n).digest())
    h[0] &= 248                                    # "clamping" as for Ed25519
    h[31] &= 63
    h[31] |= 64
    return int.from_bytes(h, "little")


def blinded_key(A: bytes, period: int, duration_minutes: int) -> bytes:
    """A' = h·A：指定周期使用的服务公钥。"""
    return _encode_point(_multiply(blinding_factor(A, period, duration_minutes), _decode_point(A)))
```

这一机制使服务向 HSDir 展示的公开身份，随时间周期变化。

随机数材料 `N` 包含周期编号和周期长度，分别编码成八字节。改变周期就会改变 `N`，进而改变派生标量与盲化公钥。因此，今天存储描述符的 HSDir 不会自动知道明天同一个长期服务身份对应什么，除非已经知道 onion 地址。

`"Derive temporary signing key"` 域字符串最后有一个零字节，完全遵循规范编码，使这次 SHA3-256 运算与其他哈希用途区分开。

三次比特运算实现 Ed25519 标量的**钳制**：

| 操作 | 效果 | 目的 |
|---|---|---|
| `h[0] &= 248` | 清除最低三位 | 使标量成为 8 的倍数 |
| `h[31] &= 63` | 清除最高位 | 保持标量在规定范围 |
| `h[31] \|= 64` | 设置第 254 位 | 确保高位格式正确 |

**`int.from_bytes(h, "little")`** 也非常容易出错。Ed25519 标量采用小端编码，不同于许多 Tor 协议字段。字节序错误产生的盲化密钥在形式上可能完全正常，但数值不正确，结果往往只是不断查询失败。

`_multiply` 在教学客户端中自行实现标量乘法。手写曲线运算适用于教学和与参考结果比较，**不能作为生产密码学代码使用**：它没有进行性能优化，也不保证抵抗时间侧信道。

## 时间周期

`time_period_info()` 只计算周期号及当前/上一期 SRV 的选择标志，**不会从共识提取 SRV 值**。本例没有使用 SRV 计算 HSDir 环；此教学模块的测试周期时长取自投票间隔，而不是解析共识中的 `hsdir_interval`。八分钟属于特定网络配置。

```python
t = time_period_info(valid_after, voting_interval, test_network=True)
Ap = blinded_key(A, t.period, t.duration_minutes)
```

`time_period_info` 根据投票间隔计算周期号并返回选择当前或上一期 SRV 的标志，但不会取得 SRV 值；完整的 HSDir 环计算还需要额外步骤。

时间周期与 SRV 阶段有意错开。客户端必须根据目前在轮换周期中的位置，选择正确的当前或上一期 SRV。组合错误时，可能得到数学上有效、但时间上不正确的 HSDir 环。

私有网络将周期缩短到**八分钟**，方便单次实验中观察。`test_network=True` 启用相应的实验网络解释规则。

## 下载与解密

**环定位与实际下载是两个独立步骤。** `responsible_hsdirs()` 可根据共识 HSDir 的 Ed25519 身份、SRV、周期和参数推导候选节点。`download_descriptor(blinded, path)` 不会调用它，而是通过 `BEGIN_DIR` 向调用者提供的路径末端发送 `/tor/hs/3/<base64-blinded-key>`。此例末端 `006e` 是人工指定的。

**教学模块尚未实现受限发现。** 解密内层时没有使用授权客户端 x25519 密钥从 `auth-client` 恢复描述符 cookie。真实受限发现必须取得该 cookie；参见[实验 13](实验-13-受限发现.md)。不能声称当前代码可以解密受保护的描述符。

**代码中的安全检查：**`parse_descriptor()` 会验证 08 型证书绑定到预期盲化密钥并由其签名，检查描述符签名以及 `descriptor-lifetime` 的范围（30–720 分钟）。证书是否过期通过 `check_expiration=True` 检查，使用当前数据的客户端必须启用；默认值为 `False`，因为实验中存档的描述符早已过期。解码器不会把 `revision-counter` 与已缓存的描述符比较：这是客户端的职责。`key_from_address()` 会以 `ValueError` 拒绝任何不是 56 个 Base32 字符、或版本与校验和不正确的地址。

```python
d = download_descriptor(Ap, [relay("003r"), relay("004r"), relay("006e")])
desc = parse_descriptor(d, A, Ap)
```

实际 `download_descriptor` 仅通过 `BEGIN_DIR` 访问调用者指定的末端节点，使用盲化公钥的 base64 编码；函数内部没有环选择。

**必须使用三跳电路。** HSDir 会用 `503 Rejecting single hop HS v3 descriptor request` 拒绝单跳 v3 描述符请求。若允许这种请求，目录中继就能看到请求者真实网络地址。这与[实验 6](实验-06-目录.md)中的公开共识不同，后者适合使用单跳目录电路。

之后，`parse_descriptor` 按顺序执行三个步骤：

1. 验证描述符签名密钥证书，确认它由根据 onion 地址本地计算出的**预期盲化密钥**签发。
2. 验证描述符签名。
3. 解密外层及内层。

第一步至关重要：如果仅因为描述符自己声称一个盲化身份就信任它，等于让对象自己证明自己。

两个加密层承担不同功能：知道 onion 地址即可解密外层；若启用受限发现，内层还需要授权客户端通过 x25519 恢复 cookie。**当前教学解析器没有实现这一授权流程。**参见[实验 13](实验-13-受限发现.md)。

## 为什么排障方法值得重视？

当全部 HSDir 都失败时，教学实现将中间密码学值——盲化密钥——与正式 tor 客户端观察到的值比较。由于两者一致，错误范围被缩小到传输和请求行为，而不是椭圆曲线算术。

这种方法可以推广：**协议实验失败时，寻找一个中间检查点并与可信实现比较。** 私有网络里的正式 tor 客户端与 ControlPort 提供了许多这样的检查点。

## 实验的真实局限

由于全部八台 HSDir 都持有描述符，成功获取并不能完全验证环选择算法。可从客户端日志交叉检查：tor 实际选择的 HSDir 应位于教学实现对相同副本和周期预测的位置集合中。更有说服力的实验需要更多 HSDir，或跨多个周期系统比较。

## 实践注意事项

- 洋葱服务必须已经**启动并完成描述符发布**。网络重启后可能需要一些时间。
- 如果所有 HSDir 都返回 `404`，优先怀疑**周期计算**。可以比较相邻周期，排查时间上的差一错误。
- 遇到 `400 Invalid HS descriptor`，应检查描述符内容、授权文件及服务日志；**不能直接归因于空的 `authorized_clients` 目录**。参见[实验 13](实验-13-受限发现.md)。
- 服务地址位于 `labs/zh-Hans/实验室/net/nodes/009h/hidden_service/hostname`，每次重建私有网络都会变化。
