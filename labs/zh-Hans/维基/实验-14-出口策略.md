| 项目 | 内容 |
|---|---|

| **需要网络？** | 是，仅使用本书的私有实验网络 |

## 实验目标

通过同一个出口节点 `006e`，向 **127.0.0.1** 发起三次流建立请求：一项被临时**出口策略**拒绝的目标、一项允许且有服务器监听的目标，以及一项允许但没有服务器监听的目标。客户端将收到带原因的 `RELAY_END` 或 `RELAY_CONNECTED`。

全部操作仅针对**可丢弃的私有 Chutney 网络**。测试电路依次经过 `003r → 005r → 006e` 三个节点，不使用公共出口中继。

## 准备

从仓库根目录执行命令。首次运行前构建镜像；不同语言的实验网络共享宿主机端口，不可同时启动。

```bash
# 首次使用：make -C labs/zh-Hans/实验室 image
make -C labs/zh-Hans/实验室 start
export PYTHONPATH=labs/zh-Hans/代码
```

脚本首先确认 `9999` 端口没有服务器监听，在 `8081` 端口启动必要的本地 HTTP 服务，并尝试在 `8080` 启动另一个测试服务。随后在第一条已有的 `ExitPolicy` 前插入临时规则 `ExitPolicy reject 127.0.0.1:8080`。出口策略按**首个匹配规则**生效；这里拒绝的是**地址与端口组合**，并不是对所有地址的 8080 端口一概禁止。脚本从 `/lab/net/nodes/006e/pid` 读取准确 PID，检查进程命令行之后只向节点 `006e` 发送 HUP，不再使用范围宽泛的 `pkill -f`。

## 执行实验

```bash
python3 labs/zh-Hans/实验室/exit_policy.py
```

## 历史输出示例（非固定结果）

```text
127.0.0.1:8080 -> END 原因=EXITPOLICY 地址=127.0.0.1 TTL=1800
127.0.0.1:8081 -> CONNECTED
127.0.0.1:9999 -> END 原因=MISC
```

中文脚本使用 `原因` 和 `地址` 作为输出标签；保留协议值 `END`、`CONNECTED`、`EXITPOLICY` 和 `MISC` 不变。

- **8080 — `EXITPOLICY`：**出口节点拒绝指定地址和端口。`RELAY_END` 可以附带 IPv4/IPv6 地址以及**可选的 TTL**；历史示例中的 `1800` 不是协议保证值，附加字段也可能缺失。
- **8081 — `CONNECTED`：**已与本地测试服务器建立 TCP 流。这**不等于**已经成功获取 HTTP 页面。
- **9999 — 历史结果 `MISC`：**该端口未监听。Tor 协议还定义了 `CONNECTREFUSED` 用于目标主机拒绝连接；实验接受 **`MISC` 或 `CONNECTREFUSED`** 两种情况。

## 参考版本 Tor 0.4.9.13 的差异

原始实验使用 **tor 0.4.9.13**，在端口关闭时观察到 `MISC`，而非更具体的 `CONNECTREFUSED`。当时的源码分析认为：`getsockopt(SO_ERROR)` 已取得 `ECONNREFUSED`，但后续重新读取 `tor_socket_errno` 时得到 `EINPROGRESS`，最终回落到通用错误原因。

这是对参考运行中 tor 行为的解释，不能当成 Tor 协议的固定行为。若结果改变，应检查运行版本与中继日志。协议分别用代码 1、3 和 4 表示 `MISC`、`CONNECTREFUSED` 和 `EXITPOLICY`。

## 为什么使用三跳？

最初的单跳测试收到 `END TORPROTOCOL`。Tor 规范建议拒绝在单跳电路上直接建立外部流，但**不保证总是返回这一文本或原因**；也可能通过销毁电路来拒绝。这里使用三跳，目的是将出口策略与单跳限制分开研究。

## 安全、恢复与校验

现在用**字符串切片**插入策略，避免正则替换的转义问题；如果已有同样的规则，则停止运行。脚本还会检查端口冲突、关闭由自己创建的服务器以及电路套接字，在 `finally` 中恢复 `006e/torrc` 并尝试重新加载。**如果恢复后的重载失败，程序将明确报告错误**：文件内容恢复不等于运行中的 Tor 已采纳配置。发生突然中断时应人工检查私有网络状态。

意大利语参考验证器 `scripts/verify_labs.py::lab14` 仍逐字要求原先的 `TTL=1800` 和 `MISC`，因此在不同 TTL 或返回 `CONNECTREFUSED` 时可能**误判失败**。改进后的脚本按结果类别验证：策略拒绝、TCP 连接成功、端口关闭。

| 现象 | 检查方法 |
|---|---|
| 所有请求都得到 `TORPROTOCOL` | 确认是三跳电路；单跳只是可能的原因之一。 |
| `8081` 连接失败 | 检查本地 HTTP 服务、实际出口策略和其他规则；如果端口已被占用，脚本会拒绝启动。 |
| `9999` 没有出现拒绝 | 可能有其他程序在监听；脚本事先检查该端口。 |
| 恢复配置后重载失败 | 检查 `006e` 的 PID、日志及实际生效的配置，不要向其他进程发送信号。 |

参考资料：[Tor Specifications — Closing streams](https://spec.torproject.org/tor-spec/closing-streams.html)；[Opening streams](https://spec.torproject.org/tor-spec/opening-streams.html)。
