# 自动验证

中文版实验代码、测试与网络配置位于 `labs/zh-Hans/`。以下命令需从仓库根目录执行。**具备验证脚本不代表已执行，也不表示全部二十个实验都已自动验证。** 离线 Python 测试、Chutney 网络验证和各实验脚本相互独立。

## 离线测试

```bash
PYTHONPATH=labs/zh-Hans/代码 python3 -m pytest -q labs/zh-Hans/代码/torlab/test
```

这些测试使用本地 Python 模块与测试夹具，**不启动私有 Tor 网络或 8080 端口 HTTP 服务器**。涵盖 Tor cell 格式、目录文档、加密原语、参考测试向量、解析器、无效输入和计算结果。负面测试特别重要：应确认错误签名、失效证书和无效消息会被正确拒绝。

## 启动私有网络并验证

```bash
make -C labs/zh-Hans/实验室 start
make -C labs/zh-Hans/实验室 verify
make -C labs/zh-Hans/实验室 status
```

启动 `book` 拓扑后，Chutney 会检查当前网络的连通性；`status` 报告节点状态。首次使用需先执行 `make -C labs/zh-Hans/实验室 image` 构建镜像，**构建阶段需要联网下载 Tor、Chutney 及依赖**。容器使用 Docker `--network host`，与其他语言共享宿主机端口；EN/RU/ZH-CN 共用容器名 `torbook-network`，**不要同时启动多个版本**。

部分实验需要单独运行对应脚本：

```bash
PYTHONPATH=labs/zh-Hans/代码 python3 labs/zh-Hans/实验室/exit_policy.py
PYTHONPATH=labs/zh-Hans/代码 python3 labs/zh-Hans/实验室/restricted_discovery.py
PYTHONPATH=labs/zh-Hans/代码 python3 labs/zh-Hans/实验室/relay_early.py 8 9
```

这些实验脚本**不属于** `make -C labs/zh-Hans/实验室 verify`，可能修改临时 `torrc` 或打开本地服务。某些脚本需要在容器内部执行；请遵守对应页面的准备要求，只操作一次性私有网络。

## 网桥实验

实验 10 使用独立的 `book-bridge` 拓扑：

```bash
make -C labs/zh-Hans/实验室 clean
make -C labs/zh-Hans/实验室 start NETWORK=book-bridge
make -C labs/zh-Hans/实验室 verify
```

**注意：**`clean` 会删除完整的 `labs/zh-Hans/实验室/net/`，包括临时密钥、洋葱服务身份和状态；`book-bridge` 有十二个节点，**不包含**普通网络的 `009h` 洋葱服务。执行清理前应确认文件确实可以丢弃。

恢复标准网络：

```bash
make -C labs/zh-Hans/实验室 clean
make -C labs/zh-Hans/实验室 start
```

`verify` 只检查当前运行的网络，不会自动切换拓扑。

## 结果诊断

| 现象 | 排查方向 |
|---|---|
| 偶发失败 | 保留日志并调查原因；重试成功不代表首次失败无关紧要 |
| 每次都失败 | 按潜在回归问题调查 |
| 所有网络检查失败 | 使用 `status` 并检查权威节点日志 |
| 无效密码学输入被接受 | 检查验证器逻辑 |
| 公开数据统计不同 | 检查共识快照、日期和输入数据 |

## 发布要求

出版前，必须分别运行离线 Python 测试、Chutney 网络验证和每个被引用的实验脚本，并检查 **退出码、日志与断言**，不能只看打印结果。意大利语根目录的 `make verifica-lab` 和 `make verifica-lab-bridge` **不自动验证中文版**。每次生成的密钥、时间戳、地址和流量测量可能不同，但协议结构及测试断言应保持一致。
