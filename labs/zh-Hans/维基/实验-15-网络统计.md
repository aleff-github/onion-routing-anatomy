## 实验目的

[Tor Metrics](https://metrics.torproject.org/) 中的**部分**统计，例如中继数、标志与共识带宽权重，可以从公开共识文档重建。但**仅凭一份共识无法估计用户数**：该估计还需要中继 *extra-info* 描述符中的汇总目录请求统计、报告覆盖比例和假定的平均请求频率。得到的是**平均每日在线客户端规模的估计**，不是不同自然人的精确人数。

## 准备

与[实验 7](实验-07-路径选择.md)相同，使用 `labs/zh-Hans/数据/collector/consensus-microdesc-2026-09-23-15` 归档共识。该文件不直接纳入 Git，首次运行前执行：

```bash
make -C labs/zh-Hans data
```

如果还要验证签名，原始实验会下载目录权威证书：

```bash
curl -o labs/zh-Hans/数据/collector/certs 'https://collector.torproject.org/recent/relay-descriptors/certs'
```

**核对下载内容：**排除 HTML 目录索引与错误页面。原始证书文档的首行可以是 `dir-key-certificate-version 3`，但 CollecTor 注释格式可能先出现 `@type ...`。此外，`recent` 地址不保证包含与 2026 年 9 月历史共识匹配的签名密钥；必须查找当时有效的证书，不能把失败直接解释为共识被篡改。

## 执行实验

模块提供命令行接口：

```bash
export PYTHONPATH=labs/zh-Hans/代码
python3 -m torlab.metrics labs/zh-Hans/数据/collector/consensus-microdesc-2026-09-23-15
```

```text

flag: {'Running': 9358, 'Valid': 9358, 'Fast': 8961, 'Stable': 8199, 'V2Dir': 7674,
       'Guard': 5306, 'HSDir': 4050, 'Exit': 3177, 'BadExit': 32, 'MiddleOnly': 28,
       'StaleDesc': 21, 'Authority': 10}
total_bandwidth: 198927900
exit_bandwidth_share: 0.3308947161257923
guard_bandwidth_share: 0.7010271560701139
versions: [('Tor 0.4.9.12', 6027), ('Tor 0.4.9.11', 2520), ('Tor 0.4.9.9', 269), ...]
networks16: [('64.65', 771), ('192.42', 636), ('204.8', 598), ...]
```

这些英文键名是程序数据结构和实际输出的一部分，保留原样。

- 历史快照中有 3177 个中继带有 `Exit` 标志，但 `exit_bandwidth_share` 只累加带有 `Exit` 且**没有 `BadExit`** 的条目。约 33% 的出口份额和约 70% 的守卫份额来自共识中的 **`Bandwidth=` 权重总和**，**不是实际转发流量比例或最终路径选择概率**。两类标志可以重叠；[实验 7](实验-07-路径选择.md) 的位置带宽权重是另一项计算。
- 参考快照中十条中继记录带有 `Authority` 标志，但签名验证使用九个投票权威身份。**标志计数并非签名者名单**；若要判断额外的条目是否对应网桥权威，必须进一步对照当时的身份和目录文档，不能只根据相差一台作结论。
- `BadExit` 与 `MiddleOnly` 限制中继的角色；**仅凭这些标志不能断言节点存在恶意行为或已被攻破**。
- 某些 IPv4 **/16 前缀**内有数百个中继；这反映地址集中，**不能证明它们属于同一运营者**，也不能据此认为全部都是出口。/16 分离只是选路限制中的一项。

计数结果先按值排序，值相同时再按名称排序。没有确定性的次级排序，Python 遍历集合的顺序可能令打印顺序变化，即使数据本身完全相同。

## 估计用户数量

```bash
python3 - <<'EOF'
from torlab.metrics import estimate_users, remove_rounding
print(estimate_users(20_000_000, 0.6))    # 假设：报告请求数为两千万，覆盖率为 60%
EOF
```

```text
3333333
```

上述 **3333333** 是**假设输入**的算术结果：`floor(20_000_000 / 0.6 / 10)`，并非从该共识中读取了两千万次请求。Tor Metrics 从 *extra-info* 汇总统计获取目录请求量，用估计覆盖比例 `frac` 修正，并假设每位平均客户端每天进行 **10 次目录请求**。`frac < 0.10` 或 `frac > 1.10` 时函数返回 `None`；允许大于 100% 的轻微超额覆盖是该方法有意设置的容差。此方法估计**平均每日在线规模**，不是去重人数。公开计数为保护隐私经过舍入；示例并未自动调用独立的 `remove_rounding` 函数。

## 验证共识签名

```bash
python3 - <<'EOF'
from torlab.directory import parse_consensus, parse_certificates, verify_consensus
c = parse_consensus(open("labs/zh-Hans/数据/collector/consensus-microdesc-2026-09-23-15").read())
cert = parse_certificates(open("labs/zh-Hans/数据/collector/certs").read())
print(verify_consensus(c, cert, 9)[:2])
EOF
```

```text
(9, 5)
```

`(9, 5)` 是参考输出：九份有效签名、所需门槛五份。公开共识与历史证书不保存在仓库中，需先用 `make -C labs/zh-Hans data` 下载。如果得到 `(0, 5)`，应检查文档是否误下载为 HTML、证书有效日期和签名密钥身份，以及 CollecTor 注释 `@type ...` 与实际签名覆盖的字节范围。

## 自动验证

`lab15` 检查中继总数、出口与守卫带宽比例、用户估计计算；具备有效权威证书时，还会检查九个历史签名。

## 常见问题

- **`valid signatures: (0, 5)`：**检查 CollecTor 的 `@type` 元数据、证书密钥与历史时期是否匹配，以及 `certs` 是否意外成为 HTML 错误页面。
- **快照相关数字不同：**更换共识会改变统计结果；要通过固定数值检查，就必须使用 2026 年 9 月 23 日对应的同一份原始文件。
