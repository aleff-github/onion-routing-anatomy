# 实验 16 — 通过时间信息关联自己生成的流量

| 项目 | 内容 |
|---|---|
| **章节** | 26 — 针对网络的攻击 |
| **需要网络？** | 是，仅使用本书的私有实验网络 |
| **前置条件** | Chutney 私有网络已启动，Tor 客户端 `008c` 正常运行 |
| **预计时间** | 阅读与实验约 1–2 小时；名义发送时长为 20 秒 |
| **脚本** | `labs/zh-Hans/实验室/correlation.py` |

> **仅分析自己生成的合成流量。** 本实验不涉及观察或识别其他人的真实通信。

## 本实验实际测量了什么？

程序通过**同一个 Tor 客户端进程 `008c`** 的 SOCKS 端口 9008，创建**六条并发的合成 TCP 流**。它**不是启动六个独立的 Tor 客户端**。每条流使用不同的 SOCKS 用户名与密码，以申请不同的隔离上下文；这**不能保证**每条连接都具有一条固定且独立的 Tor 电路。

发送端记录 `sendall` 返回后的时间；接收端则在**实验者控制的本地服务器** `127.0.0.1:8095` 上记录 `recv` 接收事件。**这不是在 Tor 出口中继上被动抓包**：第二个观察点是目的地服务器，且两个时钟都位于同一台机器上。

发送端会在每条流开头发送**四字节的明文编号**。服务器存储编号，只用于评估所推断的配对是否正确；**皮尔逊相关系数的计算不使用编号**。不过目的地本来就能读取该编号，所以实验**不能证明**未知用户可仅凭被动时间观察被识别。

## 准备与执行

从仓库根目录启动对应语言的私有实验网络。首次使用先构建镜像；不同语言的网络共用宿主机端口，不能同时启动。

```bash
# 首次使用：make -C labs/zh-Hans/实验室 image
make -C labs/zh-Hans/实验室 start
docker exec -w /lab torbook-network python3 /lab/correlation.py 3
```

参数 `3` 是伪随机生成器的**种子**。它可以重现随机决策，却**不能固定时间戳、到达顺序或相关系数**：线程调度、TCP 分段及缓冲、建链延迟都会产生差异。程序使用**250 毫秒**时间桶，名义上的流量生成期为**20 秒**；整个执行过程还包括连接建立和清理。

## 参考输出（因运行而异）

```text
客户端 0: +0.24 -0.04 +0.09 +0.86 +0.00 -0.04  -> 出口流 3 匹配
客户端 2: -0.03 +0.85 +0.35 -0.07 +0.13 -0.05  -> 出口流 1 匹配
客户端 5: +0.87 -0.01 +0.27 +0.26 +0.05 +0.15  -> 出口流 0 匹配
客户端 4: +0.09 +0.32 +0.85 -0.07 +0.02 +0.10  -> 出口流 2 匹配
客户端 1: +0.24 -0.07 +0.19 +0.08 -0.03 +0.72  -> 出口流 5 匹配
客户端 3: +0.17 +0.13 +0.04 +0.13 +0.70 +0.09  -> 出口流 4 匹配
正确匹配数: 6/6
```

每行给出发送端时间序列与六条接收端序列之间的六个**皮尔逊相关系数**，按接收端流编号排列。序列记录的是**每个时间桶内的字节数**，而不是实际截获的数据包时间戳。接收端编号由连接到达顺序决定，可能改变。

对于每条发送端流，程序**独立**选择最大的相关系数；它**没有执行全局一一匹配算法**，因此不同发送流可能选中同一接收流。匹配后再用已知编号判断结果是否为 `匹配` 或 `错误`。持续不变或缺失的序列无法提供有意义的相关系数。

历史示例为 6/6，但教学验收也允许 5/6。脚本会检查六条流是否齐全、完整读取 SOCKS5 应答、报告发送线程错误、拒绝无效序列，并在正确匹配少于五条时退出并报错。

## 本实验不能证明什么？

这不是公开 Tor 网络上的成功率测量，也不能证明任意旁观者都能识别 Tor 用户。真实对手需要同时观察两个端点，还必须考虑时钟同步、采样长度、背景流量、抖动与误判。持久守卫（[实验 19](实验-19-模拟.md)）减少客户端长期暴露的新入口位置，但不能消除两端已被观察时的关联风险。

## 自动验证与常见问题

**意大利语**参考验证器 `scripts/verify_labs.py::lab16` 只检查输出的最后一行是否为 `5/6` 或 `6/6`，**并未检查子进程的退出状态**；因此不能视为完整的运行时验证。

| 现象 | 检查方向 |
|---|---|
| 正确匹配少于五条 | 可能有相似的随机节奏；在私有网络中记录种子和负载后重试。 |
| SOCKS5 错误或缺少连接 | 检查 `008c`、端口 9008、SOCKS5 协商和接收端服务器。 |
| 时间序列无法计算相关系数 | 新代码拒绝缺失或恒定的序列，不会编造匹配结果。 |
| `Address already in use` | 本地端口 8095 被旧的实验服务器占用；只停止自己启动的实例。 |
