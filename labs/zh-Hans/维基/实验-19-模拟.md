## 实验目的

本实验单独研究持久守卫的影响。在源实验模拟中，攻击者控制 5% 的守卫加权带宽和 5% 的出口加权带宽。如果每条电路都重新选择守卫，**十五天内一半客户端失守**，三个月内几乎全部失守；使用持久守卫时，六个月后的失守比例只有 18.4%。

在简单模型中，持久守卫并不降低单条电路的平均失守概率，而是**集中**风险：大多数客户端长期使用诚实守卫，在模拟窗口内几乎不暴露入口；选中恶意守卫的客户端则持续暴露。

## 准备

与[实验 7](实验-07-路径选择.md)相同，使用归档共识 `labs/zh-Hans/数据/collector/consensus-microdesc-2026-09-23-15`。此文件不随 Git 仓库分发，首次运行前须通过 `make -C labs/zh-Hans data` 下载 Tor Project 已公开的历史快照。

## 运行

```bash
export PYTHONPATH=labs/zh-Hans/代码
python3 -m torlab.simulation labs/zh-Hans/数据/collector/consensus-microdesc-2026-09-23-15 0.05
```

第二个参数是攻击者占据的加权带宽比例，此处为 5%。

## 参考输出

```text
攻击者：守卫带宽 5%、出口带宽 5%；2000 名客户端、180 天、每天 20 条电路
持久守卫     1d:  2.6%    7d:  4.4%   30d:  4.4%   90d:  9.4%  180d: 18.4%  中位数：None
每条电路重新选守卫    1d:  4.3%    7d: 27.9%   30d: 76.5%   90d: 98.9%  180d: 100.0%  中位数：15
```

以上是**中文版 Python 模块**的输出格式，攻击者配置、两种守卫选择方式和中位数标签已本地化为中文；`None` 是 Python 输出的原样技术值。数值对应指定日期的共识快照。

模拟是**确定性的**：模块固定随机种子。用同一共识运行两次应得到一致结果。如果数值不同，先检查共识文件是否相同。

- **持久守卫：**最初选中恶意守卫的客户端较快失守，随后曲线几乎水平，直到守卫轮换才出现新机会。本模拟把单个守卫按近似 **48–60 天**的已确认守卫周期更换，而不是适用于未确认守卫的默认 120 天；这**不是 Tor 实际守卫选择算法的完整实现**。真实客户端维护已抽样及已确认守卫集合，并考虑可达性和备用守卫。`GUARD_CONFIRMED_MIN_LIFETIME` 默认 60 天、`GUARD_LIFETIME` 默认 120 天，实际网络参数可能覆盖默认值。
- **每条电路重新选守卫：**每次建立电路都有机会同时选中恶意守卫与恶意出口，风险很快累积。这次模拟的首次失守时间中位数为 15 天。
- **`中位数：None`：**在 180 天观察期内，持久守卫组失守的客户端不足一半，所以中位数位于模拟时间范围之外。

参考实现还给出：

| 攻击者占有比例 | 180 天后失守，持久守卫 | 每条电路重新选守卫 |
|---:|---:|---:|
| 1% | 3.9% | 30.9% |
| 5% | 18.4% | 100.0% |

## 模型及其局限

模型包含 2,000 名客户端、180 天和每客户端每天 20 条电路。如果某条电路**同时**选中攻击者的守卫与出口，就把该客户端在当天标记为首次失守。

为突出守卫机制，模型故意忽略中间中继、家族、/16 约束、备用守卫、连接失败、自治系统级路由以及其他真实部署细节。因此结果不能直接预测现实用户的去匿名化比例。

为了提高速度，程序在累计带宽权重上使用二分查找进行抽样，而不是反复对数千台中继调用 `random.choices`。

## 自动验证

意大利语参考环境中的 `lab19` 检查的是意大利语模块的历史快照，不会自动验证中文版模块。它检查两个关键结果：持久守卫六个月后失守 18.4%；每条电路重新选守卫时为 100%，首次失守时间中位数 15 天。

## 已知问题

历史共识文件**不包含在 Git 中**。第一次模拟前需执行 `make -C labs/zh-Hans data` 并通过 HTTPS 下载。模拟本身仅依赖 Python 标准库及本地 `torlab` 模块，不必运行 Tor 或 Chutney。
