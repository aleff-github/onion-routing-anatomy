## 实验目的

**模型边界：**这是用于教学的简化统计模型，**不是 Tor 生产环境中的完整选路算法**。它没有实现中继家族、特定目的端口的出口策略、完整持久守卫筛选、IPv6 子网约束以及部分配置和 onion 服务例外。`probabilities()` 计算的是施加排除条件**之前**的候选权重占比，并非完整电路中的最终选择概率。

Tor 电路中三台中继的选择并非简单的均匀随机抽样。每台中继的选中概率与其带宽成比例，还需要根据中继类型——守卫、出口、两者兼具或都不是——以及它在电路中的位置进行加权。抽样结果还受到约束：三台不同的中继、三个不同的 /16 网络，第一跳必须是守卫，第三跳必须是出口。

本实验使用**公开共识**，而不是只有十台节点的私有网络，因为后者太小，无法展示有意义的全网比例。

## 运行实验

```bash
export PYTHONPATH=labs/zh-Hans/代码
python3 - <<'EOF'
import random
from collections import Counter
from torlab.directory import parse_consensus
from torlab.path_selection import Selector, probabilities, top_share, _relay_type, network16
from torlab.metrics import summary

c = parse_consensus(open("labs/zh-Hans/数据/collector/consensus-microdesc-2026-09-23-15").read())
r = summary(c)
print(f"中继数量：{r['relay']}")
print(f"Guard 标志带宽占比：{100*r['guard_bandwidth_share']:.1f}%    "
      f"Exit 标志带宽占比：{100*r['exit_bandwidth_share']:.1f}%")

for pos in ("guard", "middle", "exit"):
    p = probabilities(c, pos)
    print(f"{pos:<6}: 符合资格 {len(p):>5}；"
          f"前 10 名 = {100*top_share(p, 10):.1f}%；前 100 名 = {100*top_share(p, 100):.1f}%")

sel, rng = Selector(c), random.Random(7)    # 固定种子确保结果可复现
g, m, e = sel.path(rng)
# 检查选择器自己选出的默认路径
assert len({x.id_rsa for x in (g, m, e)}) == 3
assert len({network16(x) for x in (g, m, e)}) == 3
assert "Guard" in g.flag and "Exit" in e.flag and "BadExit" not in e.flag
for name, x in (("guard", g), ("middle", m), ("exit", e)):
    print(f"{name:<6} {x.name:<20} {x.ip:<16} /16 {network16(x):<8} 带宽 {x.bandwidth}")

types = Counter("".join(_relay_type(x) for x in sel.path(rng)) for _ in range(20000))
print("20000 条路径：", "  ".join(f"{k} {100*v/20000:.1f}%" for k, v in types.most_common()))
EOF
```

## 参考输出

这些数字来自历史共识及固定种子的一次示例。只有原始共识文件与代码均不变，`random.Random(7)` 才能复现相同统计；网络数据与耗时不是常数。

```text

```

省略的单条路径输出会列出具体中继；关键是三台中继及其 /16 网络必须全部不同。

- 最后一行的简写代表中继类型：`g` 是守卫，`e` 是纯出口，`d` 同时为守卫和出口，`m` 都不是。例如 `gge` 表示第一跳为守卫，中间一跳也具有 Guard 标志，末端为纯出口。
- 在此快照中，没有路径把带 Exit 标志的中继放在第一跳或中间位置，因为对应的共识权重是零。出口容量相对稀缺，应保留给真正需要出口的位置。
- 在大量抽样路径中，中间中继也具有 Guard 标志，因为守卫占据网络容量的重要部分，而且守卫并不一定不能用于中间位置。
- 原始快照的选择概率集中程度不算高：概率最高的十台出口只占出口总体选择概率的一小部分。如果全网由少数中继主导，就更容易受到攻击。

**随机种子很重要。** 最后一行是抽样结果。固定 `random.Random(7)` 才能复现；改变种子后，百分比可能略有变化。不固定随机种子会让不同运行结果之间的比较引入无谓噪声。

# 实现详解

`labs/zh-Hans/代码/torlab/path_selection.py` 约 105 行，将规范中的两部分规则转化为代码：path-spec 的路径约束和 dir-spec 的带宽权重。

## 中继类型

```python
def _relay_type(r: RelayEntry) -> str:
    """g 仅守卫、e 仅出口、d 同时为守卫与出口、m 两者都不是。"""
    g, e = "Guard" in r.flag, "Exit" in r.flag and "BadExit" not in r.flag
    return {(True, True): "d", (True, False): "g", (False, True): "e", (False, False): "m"}[(g, e)]
```

`BadExit` 是判断出口是否**可用**时不可缺少的条件。一台中继可能具有 `Exit` 标志，却同时被权威节点标记 `BadExit`；此时绝不能选择它作出口。忘记这个条件会使客户端主动把流量经过已被权威节点识别为不合适的中继。

这些字母和代码内部类型一致：`d` 表示兼具守卫与出口，`g` 表示只有守卫，`e` 表示只有出口，`m` 表示两者都不是。

## 权重计算

```python
def weight(r: RelayEntry, position: str, weights: dict[str, int], scale: int = 10000) -> float:
    """使用共识的 bwweightscale 计算 W<位置><类别> 权重。"""
    _check_position(position)
    _check_scale(scale)
    bw = r.bandwidth if r.bandwidth is not None else 0
    if isinstance(bw, bool) or not isinstance(bw, int) or bw < 0:
        raise ValueError("中继带宽无效")
    factor = weights.get(f"W{position[0]}{_relay_type(r)}", scale)
    if isinstance(factor, bool) or not isinstance(factor, int) or not 0 <= factor <= scale:
        raise ValueError("共识带宽权重无效")
    return bw * factor / scale
```

权重键名通过字符串**构造**，而不是用一长串 `if` 判断：第一个字母表示电路位置，第二个表示中继类型。例如 `Wmg` 表示`选择中间中继时，给具有守卫能力的中继使用的权重`。

还有三个重要细节：

- 没有带宽数值的中继获得零权重；负数或非整数带宽视为共识错误。
- 默认值 `scale`：缺少对应键名时，采用完整权重。
- 除以 `scale`：把共识中的整数权重转换成 0 到 1 之间的系数。缩放值是共识参数 `bwweightscale`（默认 10000），`Selector` 会从共识参数中读取。

在 2026 年 9 月 23 日的快照中，具有出口能力中继的相关中间/守卫位置权重为零，因此不会在不需要出口的地方消耗出口带宽。

## 为什么只计算一次权重？

零权重中继会从 `Selector` 的候选数组中删掉，但 `probabilities()` 仍将零权重且符合资格的中继放在结果字典里。因此输出的“符合条件数量”不一定等于实际可抽取数量。

```python
class Selector:
    """按电路位置缓存符合条件的中继与带宽权重。

    在可用候选集合上采样，不会因为某节点权重极低而意外失败。
    """

    def __init__(self, consensus: Consensus):
        self.scale = consensus.parameters.get("bwweightscale", 10000)
        _check_scale(self.scale)
        self.candidates, self.weights = {}, {}
        for pos in POSITIONS:
            candidates = [r for r in consensus.relay if eligible(r, pos)]
            values = [weight(r, pos, consensus.weights, self.scale) for r in candidates]
            self.candidates[pos] = [r for r, w in zip(candidates, values) if w > 0]
            self.weights[pos] = [w for w in values if w > 0]
```

早期版本在**每次随机选择时**都对九千多台中继重新过滤与计算权重，构建 2,000 条路径花了约 310 秒。事先建立候选列表和权重，让重复模拟的速度大幅提高。

有效权重为零的中继被立即剔除，保留它们只会产生需要再次拒绝的无效抽样。

## 通过拒绝抽样实现路径约束

教学中的 `/16` 判定只处理 IPv4。真实 Tor 可配置子网约束，也包含 IPv6（通常使用 `/32`），部分 onion 服务电路还有例外。

```python
    def choose(self, pos: str, excluded: list[RelayEntry], rng: random.Random,
               distinct_networks: bool = True, attempts: int = 1000) -> RelayEntry:
        """从符合条件的中继采样；保留 attempts 参数兼容旧接口。"""
        _check_position(pos)
        if isinstance(attempts, bool) or not isinstance(attempts, int) or attempts <= 0:
            raise ValueError("尝试次数必须为正整数")
        excluded_ids = {r.id_rsa for r in excluded}
        excluded_nets = {network16(r) for r in excluded} if distinct_networks else set()
        pairs = [(r, w) for r, w in zip(self.candidates[pos], self.weights[pos])
                 if r.id_rsa not in excluded_ids
                 and (not distinct_networks or network16(r) not in excluded_nets)]
        if not pairs:
            raise LookupError(f"该位置没有满足条件的中继 {pos}")
        return rng.choices([r for r, _ in pairs], weights=[w for _, w in pairs])[0]
```

这种实现采用**抽取并拒绝**不符合条件的中继，而不是每次都重新生成完整候选列表。大网络中的无效抽样比例通常很低，因此远比重复过滤数千个条目高效。

尝试次数上限为 1,000 次，因为在很小的网络中，拒绝抽样可能持续很久：如果几乎所有候选都位于同一 /16 网络，有效抽样就很少。尝试用尽后，`choose` 只保留兼容的中继并在其中选择；如果一个也没有，就抛出清晰的异常，而不是卡住。

两个中继只要 RSA 身份相同就视为同一个中继，而不是看它们是否为同一个 Python 对象。

> **中继昵称不唯一。** 在参考快照中有 151 个昵称共用。仅通过名字判断中继是否相同，可能悄悄破坏路径约束。

## 选择顺序

```python
    def path(self, rng: random.Random, guard: RelayEntry | None = None,
             distinct_networks: bool = True) -> tuple[RelayEntry, RelayEntry, RelayEntry]:
        """先选择 Exit，然后有效 Guard，最后选择中间中继。"""
        if guard is not None:
            guard = next((r for r in self.candidates["guard"]
                          if r.id_rsa == guard.id_rsa), None)
            if guard is None:
                raise LookupError("固定 Guard 不属于当前共识的有效候选")
        e = self.choose("exit", [guard] if guard is not None else [], rng, distinct_networks)
        g = guard if guard is not None else self.choose("guard", [e], rng, distinct_networks)
        m = self.choose("middle", [e, g], rng, distinct_networks)
        return g, m, e
```

代码**先选出口**，再选守卫，最后选中间中继。这是有意设计的，因为出口通常是要求最严格的位置：它必须允许到指定目的地的连接。最后才选出口，前面的选择可能排除所有兼容出口，迫使算法重新开始。

可选 `guard` 参数允许调用者固定第一跳。[实验 19](实验-19-模拟.md)用它模拟持久守卫。固定的守卫会先在共识的合格候选中查找（找不到则抛出 `LookupError`），然后在选择出口时按身份和 /16 网络将其排除，因此约束在这种情况下同样成立。

## 该模型有意省略的内容

**模型边界：**这是用于教学的简化统计模型，**不是 Tor 生产环境中的完整选路算法**。它没有实现中继家族、特定目的端口的出口策略、完整持久守卫筛选、IPv6 子网约束以及部分配置和 onion 服务例外。`probabilities()` 计算的是施加排除条件**之前**的候选权重占比，并非完整电路中的最终选择概率。

模块实现了主要约束，但并不是完整的生产级路径选择器。它没有实现：

- 中继**家族**：需要微描述符数据，作为书中的练习；
- 包括 filtered、confirmed、primary 守卫的完整持久守卫样本算法；
- 洋葱服务的 Vanguards；
- 流隔离与端口偏好。

包含所有真实细节的模型会更逼真，也更难理解。教学代码重在让规则与结果之间的因果关系清晰可见。
