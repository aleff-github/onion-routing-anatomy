# 故障排查

本页收录编写本书时**实际遇到过**的问题，并说明当时确认的原因。这里是历史问题记录，不应将每个症状视为所有版本的通用诊断。Docker 使用 `--network host`，实验网络与宿主机共享网络栈，各语言版本的端口存在冲突风险。

## 网络无法启动

**`docker: Error response from daemon: Conflict. The container name "torbook-network" is already in use`**  
容器可能已经停止但仍存在。先执行 `docker ps -a`，确认 `torbook-network` 确实属于**当前可丢弃的中文版环境**，再使用 `make -C labs/zh-Hans/实验室 stop`。EN/RU/ZH-CN 共用该容器名称，不要误删其他语言的容器。

**引导无法完成，节点停留在 5%**  
可能是端口冲突、目录权威无法连接或旧进程尚未退出。**不要直接运行 `pkill -x tor`**，它会终止所选容器内所有同名 Tor 进程。应先进行只读检查：

```bash
docker ps -a
ss -ltnp | grep -E ':(510[0-9]|710[0-9]|800[0-9]|900[0-9])' || true
```

确认容器是**本次专用且可丢弃**的实验环境后，执行 `make -C labs/zh-Hans/实验室 stop` 再 `make -C labs/zh-Hans/实验室 start`。同样不要使用可能匹配调用者的 `pkill -f "tor -f"`。

**节点看似已启动，却没有回应**  
异常关机后，旧的 `pid` 文件可能残留。中文版 Makefile 没有原始意大利语环境中的 `make riavvia` 目标；在确认**所有生成密钥、洋葱身份和结果都可以丢弃**后，可以重新初始化：

```bash
make -C labs/zh-Hans/实验室 clean
make -C labs/zh-Hans/实验室 start
```

`clean` 会**删除整个 `labs/zh-Hans/实验室/net/`**。上述 `start` 将重新执行网络引导，包含需要 `CHUTNEY_LAUNCH_PHASE=2` 的客户端和洋葱服务。意大利语根目录中的 `make riavvia` 不能管理中文版容器。

**`chutney verify` 报 `Address already in use`**  
可能是临时 Web 服务器占用 8080/4747，也可能是其他语言的节点占用了 ORPort、ControlPort 或 SOCKS 端口。先确定端口对应的进程。

```bash
ss -ltnp | grep -E ':(8080|4747|9008)'
```

## 区分离线单元测试与实际网络实验

```bash
PYTHONPATH=labs/zh-Hans/代码 python3 -m pytest -q labs/zh-Hans/代码/torlab/test
```

该目录中的 pytest 使用存储的测试数据和 Python 模块，**不会自动启动私有 Tor 网络或 HTTP 8080 服务器**。 `make -C labs/zh-Hans/实验室 verify` 是针对**已经运行的** Chutney 网络的独立检查；意大利语根目录的 `make verifica-lab` 也不属于中文版测试。错误 `cannot bind port 8080` 应归于尝试启动服务器的动态实验，而不是上述离线测试。

**实际网络实验失败**  
检查 `make -C labs/zh-Hans/实验室 status`；如果运行中，再检查 `000a/notice.log` 与客户端 `008c/notice.log`（如果存在）。离线 pytest 不依赖这些服务。

**某项实验首次失败、再次运行却通过**  
实验网络只有三台中间中继，因此首次建立电路偶尔可能失败。`CREATE2 rejected (command 4)` 表示收到一条 `DESTROY` cell。可在保存日志后重试，但**偶尔成功并不证明没有缺陷**；不稳定的失败也需要排查。

**只有实验 7、15 和 19 的数值测试失败**  
这些固定数字来自**意大利语根目录验证器**对 2026 年 9 月 23 日共识的检查，**不是中文版 pytest 的标准测试**。若要单独重现历史数据，首先下载相应快照：

```bash
make -C labs/zh-Hans data
```

如果**意大利语根目录验证器**缺少其 `fonti/collector/` 参考文件，会报告 **SKIP 而非 PASS**；不要把它解释成中文版 pytest 的结果。

## 各实验的具体问题

**洋葱服务停止回应，日志报告 `400 Invalid HS descriptor`**  
历史实验中曾出现空的 `authorized_clients` 目录，但错误 `400` **不能作为所有版本的确定诊断**。特别注意：**空目录不会启用客户端授权**。Tor 必须成功加载至少一个合法的 `.auth` 文件，内容格式为 `descriptor:x25519:<base32公钥>`；若授权未生效，知道地址的人可能直接连接。[实验 13](实验-13-受限发现.md) 异常中断后，应先只读检查目录、密钥和 `torrc`。更新后的脚本仅向验证过身份的节点 PID 发送 HUP，恢复失败时会保留密钥。不要使用宽泛的 `pkill -HUP -f`。

对于确认可以完全丢弃的测试网络，通常最安全的恢复方式是重新执行 `clean` 和 `start`。如果需要保留普通节点状态，原始排障流程也提供了对 `009h` 的受限服务进行清理并发送 `HUP` 的方法，但在执行之前必须确认目标仅为 `labs/zh-Hans/实验室/net/nodes/009h/restricted_service`，其中没有需要保留的密钥。**不要把这种清理流程用于真实洋葱服务。** 这种问题在英文版审计中仍要求针对参考版本独立复验。

**修改 torrc 后实验客户端退出**  
`ClientOnionAuthDir` 或 `HiddenServiceDir` 等配置项可能误用了**宿主机路径**，而 tor 实际在**容器内部**读取配置，导致启动失败。应从节点的 `DataDirectory` 推导容器路径。

**出口对所有请求都返回 `END TORPROTOCOL`**  
电路可能只有**一跳**。出口会拒绝为这种电路转发普通外部流量，以免成为开放代理。改用三跳电路。

**`LookupError: no microdescriptor for 003r`**  
客户端尚未下载微描述符；启动后等待约一分钟，再检查目录更新。

**`the relay has a different identity from the expected one`，但端口正确**  
重新创建网络时生成了新密钥；每次 `make -C labs/zh-Hans/实验室 clean` 都会改变节点身份。重新读取 `fingerprint-ed25519`。

**pcap 为空，或 `tshark` 无法解密**  
可能的原因有：抓包开始过晚、`tcpdump` 权限不足或 `SSLKEYLOGFILE` 在建立 TLS 套接字**之后**才设置。这些原因没有已验证的发生频率排序，而且并非所有 TLS 实现都会提供可用于解密的会话密钥。

## 恢复原始状态

实验网络是可丢弃的。如果无法确定当前状态，重新初始化通常更简单：

```bash
make -C labs/zh-Hans/实验室 clean
make -C labs/zh-Hans/实验室 start
make -C labs/zh-Hans/实验室 verify
PYTHONPATH=labs/zh-Hans/代码 python3 -m pytest -q labs/zh-Hans/代码/torlab/test
```

`successes:4 failures:0` 与 `53` 项检查来自参考运行，结果可能因环境而异。实际结果和跳过项需要逐一读取，不可将 `SKIP` 当成 PASS。

**警告：**`clean` 删除 `labs/zh-Hans/实验室/net/` 内的生成数据和测试密钥。在使用前确认该目录仅包含可以丢弃的实验状态。原始环境通常需要数分钟重新初始化。

## 如果没有列出你的问题

每台节点的日志位于 `labs/zh-Hans/实验室/net/nodes/<node>/notice.log`；客户端日志尤其有用。如果配置启用了 `info.log`，也可以查看更多细节。

当实验结果不符合预期时，找到一个中间检查点、与参考实现逐步比较往往最有效。容器内的正式 `tor` 客户端提供 ControlPort、响应 `GETINFO`，能够完成教学客户端尝试的大多数操作，而且经过了远比教学代码充分的测试。
