# Website

Sources of the project website: a static, multilingual site (English, Italiano, Español,
Русский, 简体中文) with no JavaScript, cookies, web fonts, analytics or third-party requests.
It is generated by `scripts/build_site.py` and is meant for GitHub Pages, but any static host works.

```
website/
├── site.toml           address, edition, release state, languages
├── i18n/<lang>.toml    every text of the site in one language (HTML fragments)
└── static/
    ├── style.css       light and dark theme (follows the system setting), responsive
    └── assets/         cover, Open Graph image (make cover), favicon
```

```bash
make site            # generate build/site/ (not tracked by git)
make site-check      # generate and check: languages, links, SEO metadata, release state
```

**Structure of the generated site.** The root is a language chooser; each language has the
same nine pages at stable addresses: `<lang>/`, `<lang>/story/`, `<lang>/book/`,
`<lang>/labs/`, `<lang>/languages/`, `<lang>/contribute/`, `<lang>/ai/`, `<lang>/license/`,
`<lang>/independence/`. All links are relative, so the site works under the
`/onion-routing-anatomy/` prefix of a GitHub Pages project site and at the root of a custom
domain alike; only `404.html` uses `base_path`, because GitHub serves it at any address.

**What the checks cover.** Every language file has the same keys as `en.toml` and no text
left identical to the English one; every page has `lang`, a unique title, a meta description,
canonical URL, `hreflang` alternates for the five languages plus `x-default`, Open Graph and
Twitter card data, exactly one `h1`, alternative text on images and the full language
switcher; every relative link and anchor resolves; links to the repository point to files and
issue templates that exist; there are no scripts and no external resources; the sitemap
lists every page; `site.toml` and the `Makefile` agree on the edition.

**Editing a text.** Change it in `i18n/<lang>.toml` for every language — the check fails if
a language is missing a key — then run `make site-check`. Placeholders such as `{{tag}}`,
`{{p:contribute}}` or `{{new}}01-typo.yml` are listed at the top of `scripts/build_site.py`.

**Distribution links.** With `release.published = false`, the site links to the Italian
files tracked in the repository. Once a GitHub release actually exists, set this option
to `true` to link to the release artifacts and checksums. This setting does not publish
GitHub Pages or make the repository public.
